This is an SKGo application: a SvelteKit frontend in `web/` whose server is written in Go. Production is one Go binary; Node runs only while building and in development.

## Where code goes

- Pages, layouts, components, universal loads (`+page.ts`, `+layout.ts`) and other client code are ordinary SvelteKit and Svelte under `web/src`.
- Server loads go in `page.server.go` and `layout.server.go`, form actions in `page.server.go`, `+server` endpoints in `server.go`, and remote functions in `*.remote.go`, each in the route directory that uses them. The request hook is Go, in `internal/serverhooks`.
- Do not write server code in TypeScript. Files that begin `// Code generated by skgo. DO NOT EDIT.` are generator output: the `.remote.ts` and `+*.server.ts` files beside Go files, whose server bodies throw, and every `skgo_gen.go`. Change the Go source and regenerate instead.
- In a Go handler, reach the request through `skgo.EventFrom(ctx)`. Give wire types explicit `json` tags; generation writes their TypeScript types, so do not write a parallel TypeScript type.

## Commands

- Use VitePlus (`vp`) for frontend tooling, from `web/`: `vp install`, `vp run`, `vp exec`, `vp dlx`. Do not run `npm`, `npx` or `pnpm` directly, and do not change the package manager version.
- Run Go commands from the application root. After changing a Go route or remote file, run `go generate ./...`; `go tool skgo dev` regenerates on its own while it runs.
- `just build` generates bindings, builds the frontend and compiles the binary; `just serve` builds and runs it.
- Before you finish, run `go tool skgo check` (or the `skgo_check` MCP tool) and `go test ./...`. For an `SKGO001`–`SKGO008` diagnostic, read `go tool skgo advice <code>` (or call `skgo_advice`) before changing code.
- The public origin is fixed at build time. Set `ORIGIN` (its default is in the `Justfile`) and rebuild with `just build`.

## Svelte

The `svelte` MCP server serves the Svelte and SvelteKit documentation and checks Svelte code.

- For a Svelte or SvelteKit question, call `list-sections` first, then `get-documentation` for every section relevant to the task.
- Run `svelte-autofixer` on Svelte code you write, and repeat until it returns no issues or suggestions.
- Offer a `playground-link` only after the user asks for one, and never for code written to this project's files.

Its pages on server code (`+page.server.ts`, `+layout.server.ts`, `+server.ts`, `hooks.server.ts`, form actions, `$env` and adapters) describe Kit's JavaScript server. In this application that code is Go, and the rules above apply.

## Verifying

Check server-rendered behaviour against the running binary with JavaScript disabled, so a client-side fallback cannot pass for the Go handler.

If the `skgo` skill is installed, read it before writing SKGo code.
