SvelteKit feature support

The server features you can use, their limits, and what skgo does not support.

These rows cover SvelteKit's server-facing features and the tooling needed to build a skgo app. Available means the current Go implementation has a working example or focused test; it does not promise every edge case of the upstream API. Limited names a narrower supported case. Not supported means skgo has no compatible implementation. Not verified means this repository does not yet establish the behavior.

The upstream links describe SvelteKit generally. skgo follows the pinned Kit 3 version, which may differ from the public documentation. Application I/O and every server endpoint belong in Go.

Linked tests check Go handlers and the production build unless explicitly identified as development evidence. The development server has focused checks and one browser check; other development browser behavior is not established.

Pages and routing

SvelteKit featureskgoBoundary or example
Svelte 5 pages, server rendering and hydrationAvailableIn production, Kit's renderer runs in Go; rendered documents carry Go's answers, and a browser check confirms Kit's client takes over a rendered page in development and production.
Client-side navigationAvailableKit's client navigates and asks Go for server load data as __data.json; data contracts check Go's answer, not the navigation itself.
Layouts, route groups and nested error pagesAvailableGrouped routes and nested loads and nested error pages have document contracts.
Dynamic and rest route parametersAvailableParameters reach colocated Go handlers; dynamic route and rest parameter contracts.
Optional parameters and parameter matchersAvailableOptional captures and paired Go matchers select loads and endpoints; matcher rejection tries the next route before 404; routing contracts.
Page and layout server loadsAvailableGo loads produce typed data in documents and __data.json; document and data contracts.
Universal JavaScript loadsAvailableA +page.ts or +layout.ts load stays TypeScript and receives the Go load's result as data. It runs where Kit runs it: native Vite/Kit in development, a pooled goja runtime during production server rendering, the browser on client navigation, and Kit's build in Node for a prerendered page. Rendered document and fetch replay contracts. Application I/O in JavaScript is outside skgo's contract.
Parent load data, URL, params and route IDAvailableGo exposes Parent and request data through EventFrom; nested example.
Load dependencies, invalidation and untrackLimitedGo has Depends and Untrack; data contracts check the dependencies Go reports and the nodes it skips when Kit asks, not every invalidation path.
Streaming load promisesAvailableDeferred Go values stream into HTML and into the __data.json a client navigation reads; stream contracts.
Expected errors, redirects and error pagesAvailableGo load and remote outcomes use Kit's page/error behavior; error page and redirect contracts.
ssr = false and csr = falseAvailableThe SPA fallback has a shell contract, and a csr = false page is served without scripts.
PrerenderingAvailableKit's build calls Go loads, endpoints and remote prerender functions; Go serves the emitted static files and redirects. Static file contracts. As in Kit, an ordinary remote query cannot be called while prerendering.
Dynamic prerender entriesAvailableskgo.Entries enumerates raw route parameters from Go during Kit analysis; static serving contract.
Trailing slash and route config optionsLimitedPage trailingSlash supports never, always and ignore, including layout inheritance and overrides; routing contracts check the production build. Endpoint-only routes use Kit's default never; authored server-only slash overrides and nonempty adapter config are refused at generation/build with a source or route diagnostic.

Requests and server behavior

SvelteKit featureskgoBoundary or example
+server endpoints and HTTP methodsAvailablenet/http handlers serve Kit routes, including QUERY; handler contracts.
Page, endpoint and action on one routeAvailableGo endpoints and classic actions share a route; handler contracts.
Cookies and request-local stateAvailableEventFrom, SetCookie and typed locals support the sign-in example; cookie and locals contracts.
Response headers from loadsAvailableGo Event.SetHeader follows Kit's duplicate-header and cookie rules; implementation.
handle and handleError hooksAvailableGo hooks cover requests and public errors; example.
rerouteAvailableA Go hook selects routes and params while preserving the alias URL; Kit's universal forwarding hook asks Go during client navigation. Handler contracts check the production build, and adapter tests run the forwarding hook in Node.
Remote validation errorsAvailableKit 3 uses handleError with kind validation; Go hooks choose public message and extra fields before the remote body runs.
Server initNot supportedInitialize shared Go state in application setup.
Server-side fetchLimitedGo exposes request-aware fetch and HandleFetch; implementation. Direct SSR socket subfetch cookie relay is limited in development; see Development. Application network I/O belongs in Go.
Custom transport typesAvailablePaired Go and Kit transport hooks preserve methods; rendering and argument contracts.
Authentication and authorizationAvailableA Go handle hook supplies session locals and a layout load guards routes; guard contract.
Content Security PolicyAvailableNonces cover rendered and streamed documents; CSP contracts.
CSRF and origin checksLimitedRemote mutations check the build-time origin; remote implementation. Classic action origin and content-type rules have handler contracts.
Environment variables and platform contextLimitedGo server code uses Go environment and request context; Kit's JavaScript server env modules and host-specific platform adapters are not skgo APIs.
Server-only module isolationLimitedKit's frontend build keeps its client/server module rules; application server logic belongs in Go, not JavaScript modules.
Server asset readNot verifiedThe Kit export is present in the SSR bundle, but there is no demonstrated asset read through skgo's Go renderer. Application I/O belongs in Go.
Server tracingAvailableWith Kit's tracing.server option on, production Go emits Kit's OpenTelemetry spans for handle, resolve, Go server loads, actions, endpoints and remote calls through the application's global Go provider, and Event.Tracing mirrors event.tracing; handler contracts and guide. In development Kit's framework spans come from Node, and Go child spans export through the Go provider.
instrumentation.serverNot supportedskgo's adapter does not declare instrumentation support, so Kit refuses src/instrumentation.server.*. Configure the OpenTelemetry provider and propagator in Go application setup.

Mutations and remote functions

SvelteKit featureskgoBoundary or example
Remote queries and argumentsAvailableTyped Go queries render on the server and answer client requests; rendering and wire contracts, and the browser check confirms the client does not refetch a query Go rendered.
Batch queriesAvailableCalls combine into one Go batch; rendering and wire contracts.
Live queriesAvailableThe initial SSR value has a document contract, and later pushes have stream contracts.
Commands and single-flight refreshAvailableGo commands refresh requested queries in the same response; refresh contracts, and the browser check adds a todo with addTodo(...).updates(getTodos()).
Remote forms, validation and file uploadsAvailableTyped fields, issues and upload bytes have form contracts, and Go decodes the bytes the pinned Kit's own form serializer writes.
Remote forms without JavaScriptAvailableNative POST returns a rendered page; handler contracts.
Classic page form actionsAvailableGo default/named actions, use:enhance and script-free posts have handler contracts.
Remote prerender functionsLimitedskgo.Prerender functions run in Go during Kit's build, for the calls prerendered pages make and the arguments Inputs lists; the binary serves the results as files. Dynamic and Validate are refused by skgo generate, so the production binary never runs a prerender function at request time; under skgo dev, as in Kit's development server, Go answers each call. Static answer contract and reuse by server rendering.
TypeScript server implementationsNot supportedRemote bodies, server loads, actions and endpoints must be Go; generated stubs throw in production and delegate to Go in development.

Build and developer tooling

CapabilityskgoBoundary or example
Create a project with svAvailableskgo new delegates to sv create and adds the Go adapter, Vitest and Storybook.
Generate Go registrations and TypeScript typesAvailableskgo generate produces typed bindings and throwing Kit stubs; generator.
Development server and hot updatesLimitedskgo dev combines Vite HMR, native Go body updates, rebuild fallback and process recovery; see Development.
Single-binary build and static assetsAvailableThe generated project's build recipe embeds the client, assets and SSR bundle in a Go binary. Node is a build-time dependency.
Go tests and a browser checkAvailablejust test runs go test over both modules. Tests of the built example (go test -tags skgo_qualification ./example/...) and of a real development session (go test -tags skgo_dev_integration ./internal/devserver) are tagged. One browser check, a Vitest test driving the Lightpanda headless browser, runs from a Go test in each and confirms Kit's client takes over a server-rendered page; in development it also sees a Go edit arrive.
Svelte and TypeScript checkingAvailableskgo check runs the project's svelte-check. It needs the type configuration svelte-kit sync generates and does not run sync itself; checker.
Vitest component tests and StorybookAvailableskgo new provisions both through upstream tooling; scaffolder.
Unified checking, linting and formattingAvailableskgo check runs goimports, go build, go vet, Staticcheck, skgo's SKGO001–SKGO008 analyzers and generation checks, plus the project's lint and format checks and svelte-check. It never edits files and has no fix mode; a diagnostic may name the command that repairs it. A missing tool is a failed check, and --json prints the report; checker and command guide.
skgo MCP check and advice toolsAvailableskgo mcp serves skgo_check, the skgo check --json report, and skgo_advice, the installed release's diagnostic guidance, over stdio; server, contract and tool reference.
MCP project inspection and version-matched documentationNot supportedBeyond its own version in the initialize reply, the MCP server does not discover the project's skgo or Kit versions, inspect routes or generated bindings, or serve documentation; issue #176.
Host-specific adapters and Node runtime deploymentNot supportedskgo uses its own adapter and a Go process; Kit's Node, serverless and edge adapters are different deployment targets.
