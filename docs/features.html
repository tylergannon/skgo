SvelteKit feature support

The server features you can use today, their limits, and what is being built next.

These rows cover SvelteKit's server-facing features and the tooling needed to build a skgo app. Available means the current Go implementation has a working example or focused test; it does not promise every edge case of the upstream API. Limited names a narrower supported case. WIP is active work, not a released feature. Not supported means skgo has no compatible implementation. Not verified means this repository does not yet establish the behavior.

The upstream links describe SvelteKit generally. skgo follows the pinned Kit 3 prerelease, which may differ from the public documentation. Application I/O and every server endpoint belong in Go.

Requests and server behavior

SvelteKit featureskgoBoundary or example
+server endpoints and HTTP methodsAvailablenet/http handlers serve Kit routes, including QUERY; browser scenarios.
Page, endpoint and action on one routeWIPShared dispatch with a classic action is in the form-actions work.
Cookies and request-local stateAvailableEventFrom, SetCookie and typed locals support the sign-in example.
Response headers from loadsAvailableGo Event.SetHeader follows Kit's duplicate-header and cookie rules; implementation.
handle and handleError hooksAvailableGo hooks cover requests and public errors; example.
handleFetch, handleValidationError, reroute and server init hooksNot supportedNo Go equivalents are exposed.
Server-side fetchLimitedRendering can call back to Go for same-origin endpoints; general application network I/O from JavaScript is not supported.
Custom transport typesAvailablePaired Go and Kit transport hooks preserve methods; browser scenarios.
Authentication and authorizationAvailableA Go handle hook supplies session locals and a layout load guards routes; browser scenarios.
Content Security PolicyAvailableNonces cover rendered and streamed documents; browser scenarios.
CSRF and origin checksLimitedRemote mutations check the build-time origin; remote implementation. Classic action rules are WIP.
Environment variables and platform contextLimitedGo server code uses Go environment and request context; Kit's JavaScript server env modules and host-specific platform adapters are not skgo APIs.
Server-only module isolationLimitedKit's frontend build keeps its client/server module rules; application server logic belongs in Go, not JavaScript modules.
Server asset readNot verifiedThe Kit export is present in the SSR bundle, but there is no demonstrated asset read through skgo's Go renderer. Application I/O belongs in Go.
Server instrumentation and tracingNot supportedKit's instrumentation.server JavaScript hook is not a Go hook. Use Go instrumentation in the host application.
