SvelteKit's own [glossary](https://svelte.dev/docs/kit/glossary) covers rendering, routing and hydration terms, which mean the same thing here. These are the terms SKGo adds.

## Bindings package

The Go package at `internal/skgo` that `skgo generate` writes for an application. It registers every load, action, remote function and `server.go` route with the runtime and holds the generated `client`, `params` and `prerender` packages. Only `config.go` in it is yours; everything else is regenerated by `go generate ./...`. See [Generated files](/docs/skgo/project-structure#Generated-files).

## goja

The JavaScript engine, written in Go, that the production binary uses to run SvelteKit's server renderer. It has no Node built-ins and runs one render per runtime at a time; the binary keeps a pool of runtimes. See [Performance](/docs/skgo/performance#The-renderer-pool) and [UI libraries](/docs/skgo/integrations#UI-libraries).

## Link package

A relative symlink at `internal/skgo/_links/<base32>` to one route directory that holds Go files, where the link's name encodes the route path. Go cannot import a path containing `[slug]` or `(group)`, so the Go compiler reaches route code through the links, and `internal/skgo/links.json` maps each link back to its route directory. The link is the directory itself, so `//go:embed` in a route's Go file finds the files beside it. The links are committed; `go generate ./...` adds and removes them as route directories gain and lose Go files. Go skips directories that start with `_` when it expands `./...`, so a link left pointing at a renamed or deleted route never breaks that command.

## Locals

The Go struct in `internal/app/locals.go` that plays the part of Kit's `App.Locals`. The `handle` hook fills it once per request and every load, action, remote function and `server.go` handler reads it, through `event.Locals` or `app.LocalsFrom(ctx)`. See [Auth](/docs/skgo/auth).

## Marker

The `var _ = skgo.Query(fn)` line that declares a remote function. `skgo.Query`, `skgo.Command`, `skgo.Form`, `skgo.BatchQuery`, `skgo.LiveQuery` and `skgo.Prerender` return a `skgo.Marker`, which carries nothing at run time; the generator reads the declaration. See [Remote functions](/docs/skgo/remote-functions).

## Origin

The scheme and host the application is served from, fixed at build time: `just build` passes it to Vite as `ORIGIN`, which `vite.config.ts` can read for Kit's `paths.origin` ([Building your app](/docs/skgo/building-your-app#The-origin-is-compiled-in)), and compiles the same value into the binary, and `-origin` overrides it. The Go server uses it to refuse cross-site form-shaped posts and non-GET remote calls, and to decide whether a cookie is `Secure`. See [Deploying](/docs/skgo/deploying).

## Prerender service

The program under `internal/skgo/prerender` that the adapter runs during `vp build`. It serves the application's loads and remote functions to Kit's prerenderer over `skgo.RunPrerenderService`, so prerendered pages are rendered with real Go data. See [Prerendering](/docs/skgo/prerendering).

## Remote ID

The string Kit's client uses to call a remote function, `<hash>/<name>`, where the hash identifies the `.remote.go` file. `Remote.ID()` returns it, and the request path is `/_app/remote/<id>`. See [Testing](/docs/skgo/testing#Testing-the-Go-server).

## Renderer pool

The set of goja runtimes the production handler keeps warm, each holding a compiled copy of the server bundle. `SSROptions.Runtimes` sizes it and defaults to one per CPU. See [Performance](/docs/skgo/performance#The-renderer-pool).

## Stub

A generated TypeScript module, such as `+page.server.ts` or `todos.remote.ts`, whose exports have the right types and whose bodies throw `skgo: implemented in Go`. Kit compiles the stubs for type checking and for the client; the Go server answers the requests. See [Project structure](/docs/skgo/project-structure#Generated-files).
