Executed the shell block generated by `skgo-native-release record` verbatim in a fresh temporary directory on macOS ARM64. The proof uses already published native-shell v0.1.0 and official core v0.46.0; both source and core tag resolve to `45e471a8e6e2677ffb8a6a49f4a680a78e7d4d21`. The published plugin digest is `1956b2dc4c64b2e67d6cb91393ff2efa9fce8f4a4a7ddf05489d438223c13b8f`. This premerge demonstration checks the generated consumer recipe, not a claim that the new publication workflow has already executed.

`recipe.sh` is the generated shell block, and `consumer.log` is its complete stdout/stderr. It exited 0, downloaded and verified the official CLI, installed an isolated official global VitePlus 1.3.0 without changing shell profiles, completed the existing updater, installed the published plugin with its checksum, built the application, and executed `open` on the resulting application.

Process inspection showed the launched executable belonged to this fresh directory (PID10939). Computer-use inspection selected that exact .app path and observed a TinyNative window with the text `initial`.

The complete candidate → qualification → publication → published-install chain for the newly generated release remains a postmerge proof. The original Actions API and cross-repository protocol are additionally covered by focused HTTP/CLI fixture tests.

The final recipe was rerun after splitting the PATH assignment/export for ShellCheck. It again exited 0 and built the application in a second fresh directory. Running that exact newly built executable with the argument `public-release-recipe-proof` exercised the generated Swift query and command; `query-command.log` records the actual before/after results. ShellCheck passes for the saved recipe.

Machine-state scope: the final saved isolated recipe preserves the existing VitePlus default and disables shell-profile setup. An earlier exploratory recipe used a non-isolated `vp upgrade 1.3.0`, which changed the shared default; root restored the session's initial1.4.0 afterward. The saved successful proof describes the final isolated recipe only.

The query/command log also contains `context deadline exceeded` from the pre-existing example host's graceful-shutdown timeout after both query results printed. This proof establishes the generated calls and build/open recipe; it does not establish a clean shutdown or broader application lifecycle behavior.
