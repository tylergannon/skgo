# Link tree: making `src/routes/(group)/[id]` an importable Go package

**Purpose.** Full record of the junkyard's demonstrated scheme for giving a route directory
with illegal import-path characters (`(`, `[`, `]`) a valid Go import path via a generated
symlink tree plus a `go.mod` boundary, and exactly how the Go toolchain behaved with it.
This is the load-bearing mechanism the new skgo brief reuses (with a different placement).

All paths relative to the token cache root `ephemeral/inspiration/`.

## The problem, stated precisely

`go list ./...` / `go build ./...` walk every directory under the module and fail on
`app/src/routes/(group)/[id]` with
`malformed import path ".../app/src/routes/(group)/[id]": invalid char '('`
(`junkyard/ephemeral/route-go-colocation/orientation.md:L50-L52`,
`junkyard/ephemeral/worklog/route-go-colocation.md:L15-L17`). Two things are needed:

1. a **legal alias** for the directory that Go can import, and
2. a way to **stop the parent module from walking into the real directory**.

## The scheme (frozen contract, as shipped)

Source: `junkyard/ephemeral/route-go-colocation/core-progress.md:L7-L108`.

### Where links live
`<GoRoot>/.skgo/links/<enc>` — a *directory symlink* to the authored route directory.
`.skgo/links` was chosen over a non-dot name because a dot-directory is invisible to
`./...` for free (`orientation.md:L102-L105`). Consequence: `go list ./...` never lists the
link packages (`proof/run-slice.mjs:L779-L783`; validated in
`validation/final-01.md:L53-L57`), so anything that must build them has to name them
explicitly — hence `skgo test`.

### Encoding of `<enc>`
Lowercase RFC 4648 base32, no padding, of the **GoRoot-relative slash path of the authored
directory** (`core-progress.md:L32-L35`). Injective by construction; no route-syntax
renaming, no collision table. Verified from the validation report:

```
base32("app/src/routes/(group)/remotes/[id]")
  = mfyhal3tojrs64tpov2gk4zpfbtxe33voaus64tfnvxxizltf5nwszc5
```
(`validation/final-01.md:L50-L52`; decoded independently while indexing.)

An earlier illustrative scheme (`generated/skgroup-group/sk-param-id`) appears in the issue
text (`route-go-colocation/issue-07.json`, "Demonstrated compiler behavior"); it was
explicitly non-normative and replaced because it needs a collision table.

### Import path
`<module>/.skgo/links/<enc>` — used by `packages.Load`, the provider stage, the generated
registrar, and `go test` (`core-progress.md:L40-L42`). The registrar import line looks like
`"example.com/skgofixture/.skgo/links/mfyhal3t..."` (`proof/run-slice.mjs:L929-L935`).

### Module boundary
`<AppDir>/src/routes/go.mod` — a minimal file created by skgo when absent, with a
`Code generated by skgo` marker (`run-slice.mjs:L764-L767`). An authored `go.mod` already
present is preserved verbatim. skgo records whether it owns the boundary
(`core-progress.md:L36-L38`). Its only job is to make the parent module's `./...` skip the
subtree; the nested module is never built as a module in its own right.

### `<GoRoot>/.skgo/links.json`
```json
{
  "schemaVersion": 1,
  "linkRoot": ".skgo/links",
  "boundary": { "path": "app/src/routes/go.mod", "owned": true },
  "links": [
    { "link": ".skgo/links/mfyhal3t…", "target": "app/src/routes/(group)/remotes/[id]" }
  ]
}
```
(`core-progress.md:L44-L60`; asserted field by field at `run-slice.mjs:L741-L762`.)
Everything is GoRoot-relative so `skgo test` needs no other configuration.

### Ownership and pruning
- Only links recorded in the previous `links.json` are unlinked, and only after confirming
  the path is still a symlink pointing at the recorded target
  (`core-progress.md:L104-L108`).
- An skgo-owned boundary is removed only when its bytes still match what skgo wrote.
- A **rejected** generation (placement collision, escape, reserved name, missing
  registration) must remove exactly the links and boundary *that run created* — the first
  strict gate run caught the boundary file left behind after rejection, and relaxing the
  "tree unchanged" assertion was refused (`core-progress.md:L93-L102`,
  `worklog/route-go-colocation.md:L23-L32`).
- `--check` is read-only: creates no link, no boundary, no `links.json`; a missing link is
  reported as drift (`core-progress.md:L86-L91`).

### `skgo test` wrapper
```
skgo test [-C DIR] [go test flags] [packages] [-args ...]
```
(`core-progress.md:L62-L84`). Reads `links.json`, prefixes each link with `./`, inserts
them into the package list **before `-args`** and after any user packages, dedupes, and
`exec`s `go test` with cwd `GoRoot`, forwarding exit status. Two real bugs found in review:
- `-C DIR` was forwarded to Go but the inventory was read from the wrong root, so route
  tests silently did not run (`reviews/sol-01.md:L28-L42`);
- appended packages landed after `-args` and became test-binary arguments
  (`reviews/sol-01.md:L44-L55`).
Both fixed by `0590b09` (`reviews/sol-02.md:L25-L27`).

## How the Go toolchain behaved (Go 1.27.1, macOS arm64, darwin/arm64 only)

| Command | Behaviour | Source |
|---|---|---|
| `go list ./...` | Clean; lists only ordinary packages, never the link address | `orientation.md:L50`, `run-slice.mjs:L769-L783` |
| `go build ./...` | Clean (log empty) | `validation/final-01.md:L53-L55` |
| `go vet ./...` | Clean | `orientation.md:L50` |
| `go mod tidy` | Clean | `validation/final-01.md:L53-L55` |
| `go run ./cmd/app` | Executes through the symlinked import | `orientation.md:L50-L51` |
| `go test ./.skgo/links/<enc>` | Runs the route package's tests; a deliberate failure propagates FAIL and exit 1 | `orientation.md:L53-L54`, `run-slice.mjs:L846-L876` |
| `go test -race -run X ./... ./.skgo/links/<enc>` | Flags forwarded unchanged | `run-slice.mjs:L829-L844` |
| `go list -json` on a link package | **Reports `Dir` as the symlink path, unresolved** | `orientation.md:L55-L57` |
| `filepath.WalkDir` | Does **not** follow symlinks | `orientation.md:L17`, `worklog:L12-L14` |
| `gopls check <authored file>` | No diagnostics, exit 0 | `validation/final-01.md:L68-L74` |
| `gopls definition` on `var GetMessage = remote.Query(...)` | Resolves `remote.QueryBinding[GetMessageInput, Message]`; an earlier scratch run showed `invalid type` that was not reproduced against the full candidate | `fixture-progress.md:L25-L30`, `run-slice.mjs:L920-L927` |
| `gopls definition` from the registrar's link import | Resolves to `package messages` | `run-slice.mjs:L929-L945` |

The `go list -json Dir = symlink path` fact is "the single fact the whole change hinges on"
(`orientation.md:L55-L57`): `packages.Load` hands back file paths under the link, so the
generator must carry two paths per package:

- **link path** — `packages.Load`, provider staging, `go test`, registrar import;
- **authored path** — TS sibling placement, provider write-back (`jsonschema_gen.go`,
  `jsonschema/`), discovery of the author's `//go:build jsonschema` stub, inventory
  (`orientation.md:L59-L70`).

Do not rely on `EvalSymlinks` alone to map link → authored for pruned/stale links; keep the
mapping in `links.json` (`orientation.md:L78-L80`).

### Provider staging through links
The go-gen-jsonschema provider copies the module to a temp stage (only `go.mod`, `go.sum`,
`*.go`) before running, because its `-no-changes` mode is not read-only
(`orientation.md:L23-L28`). Because `WalkDir` ignores symlinks, the stage must
**materialize link targets as real directory copies at the link-shaped path**, run the
provider against `./.skgo/links/<enc>` inside the stage, then copy `jsonschema_gen.go` +
`jsonschema/` back to the authored directory (`orientation.md:L83-L86,L108-L109`;
proven by `TestRouteColocatedGenerateEndToEnd`, `core-progress.md:L112-L115`). The nested
`src/routes/go.mod` is copied along and keeps the boundary in the stage.

### What Kit sees
Nothing. Vite and Kit never touch the symlinks; the `.remote.ts` sibling sits at the
authored path and Kit hashes that path (`orientation.md:L41-L43`;
`fixture-progress.md:L14-L16`).

## What failed or was never tested
- Linux / Windows: untested. Junction/symlink semantics on Windows are an open risk;
  `path.relative(...).replaceAll("\\", "/")` in the capture plugin hints the authors thought
  about it for TS, not for Go links.
- Multi-platform gopls: only macOS arm64, single run (`validation/final-01.md:L95-L97`).
- Two-directory collision: injectivity is by construction, never exercised with two route
  packages.
- Nested boundary edge: a route package that itself contains a `go.mod` (authored) is
  preserved but the interaction with `go mod tidy` at the parent was not exercised.

## Reusable verdicts (against the new brief)

The new brief: root-route Go files symlinked *individually* to avoid picking up `go.mod`;
`//go:generate skgo gen-bindings --src-root ../ --svelte-routes ../app/src/routes`; the
route tree gets its own `go.mod` so the parent's `./...` never walks in.

| Technique | Verdict | Notes |
|---|---|---|
| Directory symlink under a dot-directory link root, base32 of the relative path | **KEEP** | Injective, deterministic, no collision table, `./...`-invisible. Keep base32 even if the link root moves. |
| `src/routes/go.mod` boundary, owned/marker-tracked | **KEEP** | The new brief already adopts it. Keep the "Code generated by skgo" marker and owned-bytes check so an authored boundary is never clobbered. |
| One link per *directory* (package) | **KEEP WITH CHANGES** | Fine for `(group)/[id]/` subdirs. For files directly in `src/routes/` (the root route), the directory *contains* the boundary `go.mod`, so a directory link would import a package whose dir has a `go.mod` — Go treats it as a different module. The new brief's answer is per-file symlinks for the root route only. Junkyard never exercised the root-route case. |
| `links.json` inventory with link→target, boundary ownership | **KEEP** | Drives pruning, `skgo test`, and stale-link drift. Cheap, self-contained. |
| `skgo test` thin wrapper (insert `./<link>` before `-args`, honour `-C`) | **KEEP WITH CHANGES** | Needed only because `./...` cannot see dot-dir links. Alternative worth considering under the new brief: put the link root in a non-dot directory (e.g. `skgo_routes/`) so plain `go test ./...` reaches them and no wrapper is needed; the junkyard chose dot-dir because of gopls worries that did not materialize (`orientation.md:L102-L105`). Decide once, early. |
| Two-path split (link path vs authored path) in the generator | **KEEP** | Unavoidable given `go list -json Dir`. |
| Stage materialization for the jsonschema provider | **KEEP WITH CHANGES** | Only if the new generator keeps a copy-to-stage provider step. If `gen-jsonschema` is run in place with `-no-changes` semantics fixed, the stage disappears. |
| Rollback of setup on rejected generation | **KEEP** | Real bug, real fix; make it a Go test. |

## Gotchas and traps
- `go list -json` `Dir` is the symlink path → every "where is the authored file" decision
  needs the inventory mapping (`orientation.md:L55-L57`).
- `filepath.WalkDir` skips symlinks silently — both scanner and any stage copier break
  without explicit handling (`worklog:L12-L14`).
- Removing the boundary reproduces `invalid char '('` instantly; a stale/absent boundary is
  the first thing to check when `./...` explodes (`orientation.md:L50-L52`).
- Dot-dir link root: `go build ./...` does **not** compile the link packages, so a
  colocated package that only the registrar imports gets compiled via the registrar, but a
  route package nobody imports is never compiled by `./...` — only `skgo test` would find it.
- The provider's `-no-changes` is not read-only (`orientation.md:L27-L28`).
- `go.mod` needs `tool github.com/tylergannon/go-gen-jsonschema/gen-jsonschema`
  (`fixture/backend/go.mod:L22`) for `go tool gen-jsonschema` to resolve.
- Kit's ID is a hash of the authored TS module path; renaming a route dir changes the ID
  (`run-slice.mjs:L634-L717`), so regeneration must prune the old link *and* the old
  `.remote.ts`.
