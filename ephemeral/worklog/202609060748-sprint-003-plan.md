decision: remote In/Out shapes prefer an array of entries over an arbitrary map — `[]struct{Name string; ...}` rather than `map[string]V`. Not merely a concession to the admitted type set: order is preserved, keys need not be strings, entries can gain fields without restructuring, and the client builds its own lookup in one line (`new Map(items.map(...))`) if it wants O(1). Kit itself encodes `Map` as `[key, value]` pairs on the wire (the `__skram` reducer we ported), so this matches the framework we mirror. Map genuinely wins only for large unbounded user-defined key sets used purely as lookup (i18n catalogs, flag blobs), which is not on skgo's path.
