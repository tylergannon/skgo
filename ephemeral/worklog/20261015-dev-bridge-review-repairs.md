# Development bridge repair decisions

- decision: Kit 3.0.0 starts server loads independently and only awaits ancestors when `parent()` runs. The existing native load HTTP exchange now carries a demand frame and Kit's parent reply in full duplex; the existing Go branch engine skips its synthetic parent node unless Parent requests it. This avoids a second scheduler or per-load request registry.
- correction: Snapshot subtraction per callback cannot propagate shared response headers correctly under concurrent loads or Server-Timing accumulation. Native request ownership now tracks the emitted snapshot for each actual Go responseState under its lock; action effects come from the action's actual state, including without middleware.
- correction: A fetch continuation body is payload, not HTTP metadata. JSON continuation requests now travel in response bodies. Native Fetch URL/redirected/type properties require explicit restoration, including on Response clones; a Go response substitution must not inherit a discarded continuation's metadata.
- decision: An optional Web Response body read cannot define request lifetime. Go owner cancellation removes every exchange and JS owner cancellation aborts still-uploading/unread response streams. Raw Web streams need reader.cancel on abort: destroying only the HTTP request leaves an iterator blocked in its next body read.
- correction: Concurrent HandleFetch next calls cannot share one reply channel; each continuation needs its own reply so Go goroutines receive the matching response. The same exchange serializes transport steps without owning application scheduling.
- friction: Broader focused race verification exposed an existing abandoned-prerender reporter race: its closure captured r while the handler reassigned r.WithContext. Capture the immutable callback path before starting the reporter.
- correction: Independent review caught that a per-continuation reply channel does not extend net/http request-body ownership. Returning the next instruction from the upload handler closed an earlier response body under concurrent Go readers. Upload acknowledgment and next-step negotiation now use separate HTTP operations; the upload handler stays until its Go consumer reaches EOF, closes the body, or the owner cancels. An upload-accepted gate prevents a reordered next-step request from overwriting a pending reply. The regression now deliberately postpones the first body read until the second continuation returns; a separate producer cannot finish until the first forwarded chunk is consumed, preserving a load-bearing streaming control.
- correction: Explicit continuation Body.Close must not call net/http's server request-body Close first: that method drains an unfinished upload and can block the Go hook indefinitely. The continuation wrapper now releases its upload handler immediately; the 204 acknowledgment cancels that specific JS producer, and net/http closes its own request body after handler return. The joined regression retains the independent review's 700ms bound and additionally requires producer cancellation before the substituted final response is consumed.
