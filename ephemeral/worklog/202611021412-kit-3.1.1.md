# Kit 3.1.1 adoption

decision: Registry-verified @sveltejs/kit stable is 3.1.1 (published 2026-10-29T23:48:42Z); SKGO v0.45.1 and main pin 3.1.0. Svelte 5.57.3, svelte-check 4.7.8 and vp 1.4.0 are also newer but outside this repair; Kit 3.1.1's peers (svelte ^5.57.1, vite ^8.0.12, typescript ^6) are satisfied by the current pins, so the Kit pin moves alone.
discovery: Kit 3.1.0 -> 3.1.1 leaves `src/core/postbuild/queue.js` byte-identical (stock dbe8bbac…, corrected 400bf345…, patch 0d35d370…). The queue correction is re-packaged under the 3.1.1 name with the same digests; only the version string and correction ID change.
decision: `adapter.go`, `kitpatch.go` and `prerender.js` no longer spell the Kit version; Go derives the compat asset names from `toolchain.Kit`, and prerender.js derives them from the adapter package's exact `@sveltejs/kit` peer (as dev.js already did). A pin advance is now `toolchain.Kit` + `package.json` peer + asset rename + examples, with the kitpatch metadata guard refusing any mismatch.
friction: A single `sed` pass with two ordered substitutions on development_version_test.go double-applied (3.1.0->3.1.1 then 3.1.1->3.1.2 on the same line). -> edit version tables with exact-line replacement, not chained regexes.
friction: `pnpm peers check` from the 3.1.0 journal is not a vp 1.3/1.4 command (`vp pm peers check` -> "Command 'peers' not found"). `vp install --frozen-lockfile --offline -- --config.strict-peer-dependencies=true` is the equivalent and passed; the `[WARN] Issues with peer dependencies` line printed by the non-frozen install is pnpm's generic notice.
discovery: On a consumer created by v0.45.1 (Kit 3.1.0 installed, `@sveltejs/kit@3.1.0: patches/skgo-kit-3.1.0-queue.patch` configured), this checkout's `kit-patch --apply` refused twice: first "installed Kit is @sveltejs/kit@3.1.0; supported package is @sveltejs/kit@3.1.1" (checkInstalledIfPresent), then it would have hit "conflicting Kit patch entry" (checkPatchMap). The documented existing-project procedure could not advance a Kit pin at all; this is the first pin advance since kit-patch shipped in #351.
decision: kitpatch now (a) treats an installed Kit of another version as what the required native install replaces instead of refusing, (b) supersedes skgo's own earlier `@sveltejs/kit@<v>` -> `patches/skgo-kit-<v>-queue.patch` entry and deletes that file, while foreign Kit patch entries still refuse, and (c) Verify refuses while an earlier owned entry remains. `update.applyFrontend` deletes owned Kit patch files absent from the stage so `skgo update` leaves no orphan.
friction: `TestCheckPassesOnTheUnmodifiedExample` fails under `vp exec go test` locally ("export data version 5 is greater than maximum supported version 4" from staticcheck) but passes as CI runs it (`PATH=.tools/bin:$PATH go test`). The vp exec environment changes what staticcheck's `go list` sees; run qualification-tagged tests without vp exec.
friction: `skgo new` requires global VitePlus exactly 1.3.0 while this machine's global vp is 1.4.0 -> a PATH shim to `~/.vite-plus/1.3.0/bin/vp` qualifies a checkout without touching the user's global install.
decision: Consumer proof pre-publication = real `skgo new` from the checkout (file: adapter pack + file: sv add-on + --skgo-replace, --skgo-version v0.45.1 for a valid semver) plus the documented existing-project path (`kit-patch --apply`, native install, `--check`, go.mod replace, build/serve) on an app created by main's toolchain with authored edits. `skgo update` end to end needs the published adapter/add-on/module and is a post-release check.
friction: `skgo new` flags must precede DIR (`skgo new [flags] DIR`); a trailing flag list exits with usage.
friction: Appending a second `overrides:` block to a generated pnpm-workspace.yaml makes pnpm refuse the duplicate key; merge into the existing block.
discovery: A fresh app's own `skgo check` reports staticcheck S1021 on generated `server.go:50` and `svelte-format` failing for want of project Prettier; both come from the unchanged scaffold templates, not Kit, and are left for a separate fix.
