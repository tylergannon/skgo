# dropping `skgo.None` (issue #20) — corrections and traps

## The generator cannot fix its own stale output, and this change invalidates it

`skgo generate` loads the app's packages with `packages.Load` and refuses on any
package error (`internal/gen/scan.go`, the `packages.Visit` block). The
registration file it wrote on a previous run is one of those packages' files.
So the moment a constructor's signature changes — which is exactly what this
change does — `go generate ./...` fails with

    skgo_remotes_gen.go:10:57: in call to skgo.NewQuery, type
    func(ctx context.Context) (Site, error) of getSite does not match
    func(context.Context, In) (Out, error)

and the run that would have rewritten that file never happens. The example was
bootstrapped by hand-patching the six stale calls to their `NoArg` form and then
regenerating; a downstream app upgrading past this commit has to do the same, or
delete every `skgo_remotes_gen.go` first.

Worth removing rather than documenting: the generator could ignore errors in
files it owns, or delete them before loading. Not done here — the load error
arrives as one `go list` blob with the file name inside the message rather than
in `Error.Pos`, so recognising "this error is in my own output" is textual, and
that deserves its own change.

## The empty payload is kit's sentinel, not devalue's encoding of `undefined`

Both `stringify_remote_arg` and `stringify_command_arg`
(`runtime/shared.js:252`, `:265`) short-circuit `if (value === undefined) return
''` **before** calling devalue. devalue's own encoding of `undefined` is the
literal `-1` (pinned in `devalue_wire_test.go:113`), which would base64 to `LTE`
and match nothing. So "no argument" is `''` by kit's decision at exactly two
call sites, and `parse_remote_arg`'s `if (!string) return undefined` is the only
thing that reads it back.

A no-argument query's refresh key is therefore `<hash>/<name>/` — `id`, a slash,
and nothing. `split_remote_key` splits on `lastIndexOf('/')`, which is what makes
that round-trip. Verified live against a freshly scaffolded app: the command
response carried `{"1086sy4/status/":{"v":…}}`.

## Kit decides "takes no argument" by the factory's arity, and the validator is load-bearing

`query(fn)` with one argument means no validator, and `create_validator`
(`runtime/app/server/remote/shared.js:12`) then installs `(arg) => { if (arg !==
undefined) error(400, 'Bad Request') }`. The generated stub's no-validator form —
`query((): T => unimplemented())` — is what installs that. Emitting the
`'unchecked'` two-argument form for a no-argument function would silently accept
arguments kit refuses. The stub bytes did not change in this commit, which is the
evidence the wire did not.

## The compiler no longer checks a marked function's shape; `skgo generate` does

`skgo.Query` takes `any`, so a misshapen remote function is no longer a compile
error at the declaration. The generator reads the real signature
(`remoteSignature` in `internal/gen/scan.go`) and its message is now the entire
diagnostic a developer gets — hence `TestAFunctionSkgoCannotPublishIsRefusedByName`
pinning that each refusal names the function, its actual signature, and the shape
expected. `skgo.Form` keeps its generic constraint: a form always receives the
submission, so there the constraint does real work.

## Refreshing a no-argument query needs its own name

`Refresh[In, Out]` infers `In` from the argument, and a no-argument query has
none to infer from — Go cannot unify `func(context.Context) (Out, error)` with
`func(context.Context, In) (Out, error)`. Hence `RefreshNoArg(ctx, fn)`. The
alternative, a variadic `Refresh[F any](ctx, fn F, args ...any)`, would have
dropped the compile-time check that a refresh names an argument of the query's
own parameter type, which is the property that makes `Refresh` safe at all.
