## Sprint 002 build

decision: cross-agent contract pinned up front — module `src/lib/todos.remote.ts` (hash `worolc`) exporting `getTodos` (query), `getTodo` (query, string id), `addTodo` (command), `watchCount` (query.live); seed todos `t1`/`t2`.
discovery (captured from the built client in Chromium, not from docs): `GET /_app/remote/worolc/getTodos` omits `payload` entirely when the arg is undefined; `getTodo` sends `?payload=WyJ0MiJd`; `addTodo` POSTs `{"payload":...,"refreshes":["worolc/getTodos/"]}`. The refresh key ends in a trailing `/` with an EMPTY raw payload — split on the LAST `/`. The command response must return the refreshed value in `q["worolc/getTodos/"].v` with `r:true` or the list never updates. One request per add, so the single-flight assertion is real.
correction: `vp dev` is NOT broken — that report was a misdiagnosis. "The configured Vite SSR environment must be a RunnableDevEnvironment" comes from kit's `src/runner.js`, whose own comment says the check is an `instanceof` that fails across Vite instances. There are three `vp` binaries on this machine (project-local, mise-global `npm:vite-plus`, `~/.vite-plus/bin`); the mise-global one ships its own `@voidzero-dev/vite-plus-core`, so a dev server it creates carries classes from a different module realm than the kit the project resolves. Sprint 001 already documented this in `example/Procfile`, which runs `node_modules/.bin/vp` explicitly. Running bare `mise x -- vp dev` from the wrong PATH is what failed. Fix: `example/mise.toml` now sets `_.path = ["./web/node_modules/.bin"]`, so even the bare name resolves to the project copy. Verified: `mise x -- vp dev` serves `/todos` with 200 and the SSR program reloads.

discovery: `devalue.Undefined` (not `nil`) is JS `undefined`; `nil` is `null`. `ParsePayload` returns `(nil,false,nil)` for both an empty payload and one that decodes to undefined.
