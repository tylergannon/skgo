# Prerender failure isolation

decision: The diagnostic fixture owns four authored files: its generator directive, failing Go root layout, /about page and /about prerender option. No hooks, demo consumers or successful-production routes are staged. Both fixtures share exactly the plan's six bootstrap files through the existing copy/rewrite helpers; dependencies link to this checkout's installed pin and adapter. Their builds remain separate.

decision: Installed Kit reports 3.0.0. In src/core/config/options.js, prerender.entries defaults to ['*']; src/core/postbuild/prerender.js builds prerender_map from route metadata and enqueues prerender-enabled static route IDs for '*'. The fixture has only /about as a page, explicitly prerendered, with no links or remote inputs that add crawl targets. Kit logs format_response for HTTP errors and rejects them through handle_http_error. The adapter's remoteLoad throws the positioned Go failure after compiling/invoking the generated prerender program. The named test retains independent literal route, path, source, request and error expectations.

measurement: Same command before and after: `/usr/bin/time -l go test -count=1 -v ./internal/gen -run '^TestPrerenderGoLoadFailureNamesAuthoredRoute$'`. Each invocation uses a fresh temporary app, installed frozen frontend dependencies and existing shared Go/tool caches. Caches were not cleared, dependencies were not installed between runs, and runs were sequential. Before measurements preceded replacement of preparation. All four outer commands exited 0; each frontend build intentionally failed. The after test explicitly observed vp build exit status 1.

measurement: Per selected-test invocation, before and after each request one outer Go test compilation/execution, one go generate (the app's go tool skgo), one batched vp fmt of generated frontend files, and one intentionally failed vp build. Reaching the Go load diagnostic requires the adapter's once-only generated prerender Go compilation and at least one invocation of that binary. There is no separate application go test or go test -c in this diagnostic fixture, no separate svelte-kit sync or svelte-check command, no standalone application binary build and no HTTP server start. Kit's normal build config runs one sync.all preparation pass (src/exports/vite/build/index.js:142); it writes tsconfig, manifests, server and generated types before prerender. The second source occurrence is only a watch-mode rebuild. This integrated frontend preparation is included in elapsed/CPU observations, not counted as absent work. The accepted successful fixture still separately compiles its server and its child production.test once per package invocation; sharing bootstrap does not share its build with this failure.

limit: These are setup-path counts from the executed tests and mapped callees, not exhaustive subprocess tracing. Go tool/cache compilation, package-loader commands, Kit internal preparation invocations and the copied demo's bridge invocation total were not individually traced. The original test verified failed frontend builds but did not log their numerical child exit codes; after runs log exit 1. Darwin time's reported CPU/RSS are command-tree observations, not simultaneous summed memory, per-child accounting or a cold-cache benchmark. Source isolation is demonstrated; these measurements do not establish a general CI speedup. Existing successful-production GOWORK sensitivity and earlier measurement limitations remain deferred; this task does not polish that fixture.

trap: Independent validation found that mutating an authored demo contact remote did not break a build of the already-generated links, which retained their copied source. Testing that authored nested package directly failed setup instead. The validator restored both attempts and used an actual contact-consumer compile error in the example's existing test package instead. A mutation experiment must first demonstrate the intended whole-example compile failure; merely editing an authored source is insufficient.

trap: Independent validation changed only the real adapter's Go-load diagnostic label from source to authored. Generation and both frontend bundles completed; Kit reached prerender and the real Go load failure. Only the literal source-path assertion failed, with outer exit 1 and intentional inner build exit 1. The adapter was restored exactly. This discriminates a missing positioned diagnostic from a setup failure. Separately, a missing field on the demo's generated contact Receipt broke whole-example compilation (exit 1) while all five narrow diagnostic/production tests passed shuffled without skips (exit 0); those demo files were restored exactly.

limit: The independent validator's later standalone diagnostic passed in 19.40 test seconds, outside the primary agent's two after observations. During its later mutation run it observed unrelated concurrent example browser workers and another dev application; they were left untouched. Background load was not controlled or sampled for the primary measurements. Timing variability and cache/background conditions preclude treating the recorded pair as a stable speedup.
