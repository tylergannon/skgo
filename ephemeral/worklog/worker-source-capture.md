# Worker source capture

- correction: the earlier Gimbal before/after timings used different producer paths/content and overlapped another generation run. They cannot establish a gain. Compare baseline, predicate reorder alone, and retained bytes at one physical producer path with the same application, private caches, compiler priming, and alternating order.
- decision: the synthetic capture benchmark is diagnostic only. Retain byte-cache complexity only if paired real Worker invocations demonstrate useful improvement beyond the predicate reorder.
- measurement: frozen Gimbal at `/tmp/skgo-capture-paired/app`, producer always `/tmp/skgo-capture-paired/producer`, sequence baseline/predicate/retained/retained/predicate/baseline. Each variant's compiler and one complete Worker process were primed before samples; each measured process used a new private generator cache. Six runs each contain one cold Run, three unchanged Runs and eight body edits. The body medians per run were baseline 240.058/239.056ms, predicate 225.209/224.242ms, retained 202.581/202.919ms. Combined body medians: 239.056/224.242/202.706ms; allocated bytes per edit: 37.45/31.16/11.87MB. Unchanged medians: 239.64/222.72/203.46ms. Cold medians: 3.414/3.354/3.330s, only two samples each, not a general cold-start claim. Exact outputs are in `ephemeral/worker-capture-probe/logs`; the Go probe runs from the cloned application's root. Gimbal and Polytype owners held heavy local work during this window.
- decision: retain both changes for correctness review: retained bytes saves another ~9.6% of actual warm body Worker.Run time beyond the predicate reorder and ~62% of its allocation. These measurements exclude application compilation, startup, rendering and browser reload.
- rejection: independent review and a separate reproduction both showed retained bytes returning stale data on Linux 6.12: five rapid equal-size timestamp-preserved edits all returned the prior bytes. Fresh ctime/inode/size/mtime is not a universally reliable content revision. The same existing dev digest optimization also failed its published preserved-mtime test five times and was reported to its owner. Reject the retained-byte layer rather than add a timing heuristic; keep only the measured predicate reorder (239.06→224.24ms body Worker.Run, 37.45→31.16MB allocated). Rejected code remains at commit dc681c8; the paired logs remain useful evidence, not a claim for the final patch.
- reproduction detail: the paired run copied the probe main.go into the cloned Gimbal application at `ephemeral/workerprofile/main.go`; the application go.mod replaced SKGO with `/tmp/skgo-capture-paired/producer`. Each variant was copied into that same producer directory, then `GOWORK=off go build -o /tmp/skgo-capture-paired/probe ./ephemeral/workerprofile` ran from the application root before invocation. The standalone probe module is an isolation boundary for this repository, not the configuration used for paired timings.
