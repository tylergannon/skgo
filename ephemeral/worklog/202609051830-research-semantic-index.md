discovery: kit remote id = base36(djb2 backwards over UTF-16 units) of the vite-root-relative `.remote.*` path + "/" + export; identical in dev and build (`reference/kit/packages/kit/src/utils/hash.js:L5-L23`, `exports/vite/index.js:L648-L656`). discovery: kit executes `.remote.*` modules in Node (dev SSR runner; build `analyse`) to read each export's `__.type`. Generated stubs must be real `query()/command()` calls with throwing bodies; a top-level throw or default export breaks the build. `prerender` remotes are executed at build for each input, so a throwing prerender stub fails `vp build` — deferred.
discovery: Go ignores files whose names begin with `_`; the brief's `_data.remote.go` for generated output would be dropped silently. Use `skgo_gen.go`.
decision: thin custom adapter (~60 lines, build-time only) over adapter-static SPA mode, because adapter-static emits no manifest while `Builder` gives routes/prerendered/config/fallback directly (`sources/kit/build-adapt/adapter-api.md`). Consistent with the brief's "JS only where kit requires it".
discovery: GET `query` results are applied by the client from `data.q[<id>/<payload>]`, not `data._` (`sources/kit/remote-client/client-expectations.md`). Easy to get wrong.
