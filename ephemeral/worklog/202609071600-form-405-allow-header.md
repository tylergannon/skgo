# form-nojs follow-up: the second 405 lacked its Allow header

Branch `claude/mystifying-banach-00a7ff`. Task: `runFormAction`'s 405 (a
`?/remote=` id that names no form) claimed an Allow header in its comment
and set none; make it carry `Allow: GET` like kit's
`handle_remote_form_post_internal` → `method_not_allowed_result`.

trap: `HTTPError` carries a status and a message, no headers. Any helper that
returns an `*HTTPError` without holding the `ResponseWriter` cannot set
`Allow`, so a 405 built there is silently RFC-9110-incomplete and a comment
saying otherwise is the only thing that looks wrong. Grep for
`Status: 405` / `StatusMethodNotAllowed` outside a function that has `w` when
auditing; the header has to be set at the call site that does. Both page
405s now set it in `document.go`; `runFormAction` documents that it returns
no other 405.

friction: a fresh worktree fails `go test ./example/...` with "pattern
all:build: no matching files found" until `pnpm install` + `just build` have
run in that tree — same as the previous worklog noted after a rebase.

correction: the first cut kept #58's `!ok || fn.kind != kindForm` → 405 and
wrote a test cementing it. Kit does not do that. `handle_remote_form_post_internal`
only checks `if (!form)`; a name that resolves to a query proceeds, `__.fn`
is undefined on a query's internals, the TypeError lands in
`action_error_result`, and `get_status` makes it an opaque 500 with no Allow.
Only an id that resolves to nothing is the 405. Split the check: `!ok` → 405
(Allow set by the caller), non-form → 500 "Internal Error". Lesson: when a
mission says "match kit", read the branch conditions of kit's function, not
just the function name the comment cites — the condition was the divergence.

bug (filed as #66, not fixed here): kit renders a keyed form's action as
`?/remote=hash/name/<encoded key>` (`form.js:163`) and its server resolves
the first two segments, injecting the key as the input's `id`. skgo's
`Lookup` is a flat map, so a no-JS submission of any `form.for(key)` is
refused 405 — demonstrated against the example's `sendMessage` with valid
fields. The enhanced path posts to the unkeyed id with the key in the data,
so it appears unaffected (not verified running). Not a missing feature: the
page kit already renders cannot be submitted.
