# Generated concrete closures (#65)

Actionable intelligence only. The shape and the proof are in the PR.

## The generator cannot bootstrap across a runtime API change

`loadApp` refuses any package `packages.Load` reports an error for, and the
per-route `skgo_remotes_gen.go` files are in those packages. So the moment a
change removes a runtime symbol the *existing* generated files call
(`skgo.NewQuery`), the route packages stop compiling and the generator that
would rewrite them refuses to run. Catch-22, and it is not new — it is a
property of the generator today, invisible until a signature changes.

The way through, for anyone doing this again: replace every
`skgo_remotes_gen.go` with a bare `package <name>` line, then run the
generator. `loadApp` is happy with an empty generated file. A one-liner:

```
python3 -c 'import pathlib,re
for p in pathlib.Path("example").rglob("skgo_remotes_gen.go"):
    m = re.search(r"^package (\w+)$", p.read_text(), re.M)
    p.write_text("// Code generated by skgo. DO NOT EDIT.\n\npackage %s\n" % m.group(1))'
```

A real consumer upgrading skgo across such a change hits the same wall with
no such note. Worth an issue: the generator could tolerate type errors in the
packages it is about to rewrite, or `skgo generate` could blank its own
outputs before loading.

## Codecs cannot live in the package that declares the type they encode

The import graph decides this, not taste. `generated` imports every route
package; a codec for `todos.Rename` must name that type, so it lives in
`generated`; therefore the closure that calls the codec lives there too;
therefore the route package has to *publish* the developer's unexported
function for it. Hence `Skgo_<name>` vars.

They are `var Skgo_x = x`, never `func Skgo_x(...) { return x(...) }`.
`skgo.Refresh` finds a query by `reflect.ValueOf(fn).Pointer()`, and a wrapper
has a different code pointer — `skgo.Refresh(ctx, getTodo, id)` would stop
finding `getTodo` with no error anywhere.

## Three places the bindings package must spell a Go type

Go infers none of them: a form's argument (`var in T`), a batch's argument
slice (`make([]T, n)`), and a live query's yield (`func(out T) error`). Each
is published from the declaring package as a *type alias* — `type SkgoOut_x =
int` — because an alias is the same type and needs no conversion. Adding an
alias meant the generated route file needed its own import block; a generated
file does not inherit the developer's file's imports.

## polytype's root codecs are named by position

`codegen.Generate(defs, roots, …)` names an anonymous root `Root<i>` by its
index in the slice it is handed, and `vacant()` moves it aside if a
*definition* already claimed that name. skgo spells `DecodeRoot7` into the
closures, so the order of that slice is now load-bearing and is built from a
sorted walk, never a map. `checkRootNames` refuses an app declaring a type
called `Root3` rather than letting a closure call the wrong codec.

## Two things the transport hook still owns

polytype's encoder would flatten a transported value into a plain object, and
devalue's reducer would then have nothing to recognise — the browser would get
an object with no methods, which is the bug the hook exists to prevent. So a
*result* whose type reaches a transported type is not encoded by a generated
encoder; the generated closure calls `call.Transported(out)` and devalue
finishes it. `skgo generate` decides which is which.

On the way *in* it is the opposite. The revivers passed to `devalue.Parse` for
a remote argument are now identity: they resolve the tag and hand the payload
through, and the generated decoder does the one decode there is. That is not a
weakening — for a transported type, the generated decoder *is* the function the
hook's `Decode` calls, because `skgo generate` emits both from one lowering.
Reviving first would leave the generated decoder looking at a Go value instead
of the shape it validates.

## Wire order changed, and it is kit's order now

polytype's encoder emits `*devalue.Object` in struct declaration order; the
`json.Marshal` round trip it replaced emitted `map[string]any`, which devalue
sorts. So `{colocated:…,name:…}` became `{name:…,colocated:…}`. Nothing reads
object order on the wire — kit's client does not — but a test that pinned the
bytes does (`example/ssr_test.go`). Declaration order is the more faithful of
the two: it is what kit's own devalue writes for an object literal.

Refresh keys are unaffected: `stringify_remote_arg` sorts keys, and the
argument path still goes through `roundTripValue`.

## Pre-existing failure on main, untouched by this branch

`engine-build.feature` (#80) has a scenario "A prerendered page is still the
file kit's own server build wrote", which asserts `/about` is written to disk
during the build and therefore carries no session. #79 landed after #80 and
set `export const prerender = false` in `src/routes/about/+page.ts` — its own
comment says every page in the app is now un-prerenderable because the root
layout has a Go load, and that the two claims cannot both be demonstrated
until #81. So the scenario has no fixture left: `/about` is server-rendered,
the signed-in visitor's name is in the document, and the step fails.

Neither file is touched by this branch (`git diff --name-only main..HEAD`
lists neither), and nothing about codecs can affect whether kit prerenders a
page. Left alone deliberately: rewriting the scenario would be inventing a
claim, and deleting it would drop #80's coverage. It belongs with #81.
