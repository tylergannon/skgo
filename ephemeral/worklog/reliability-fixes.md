# Reliability fixes

- decision: The user requires one shared feature branch, ordered issue groups, independent token-cache annotation before implementation, and Claude Opus validation constrained to issue goals, load-bearing proof and reproducible introduced bugs. Avoid redundant full CI and new proof machinery.
- correction: Rebasing shared application configuration across main's Entries/Reroute/validation hooks must preserve policy branches moved out of server.go. The first composition omitted the catalog validation policy; independent documentation reconciliation caught it before final validation. Regenerate route metadata after combining generator changes, and preserve same-named prior test captures under distinct filenames.
- correction: Kit invokes reroute before handle creates a logical request owner. Composing its internal reroute transport inside the application fetch exchange makes a real example build return 500 for /about. Keep the authenticated, same-origin/base-aware framework callback reachable before the owner-dependent exchange; the callback regression and actual build reproduced and verified this integration repair.
- correction: Go compile-only checks do not parse the serve-only JavaScript bridge or tagged real-session tests. A conflict left an extra closing brace in dev-bridge.js and omitted new diagnostics arguments in three tagged callers. Existing native contracts caught the syntax error; keep those tests, fix the source, and retain only one wrapper per identical browser scenario. Shared fake API declarations must include types referenced by combined configuration fields, or unrelated generator assertions never execute.
- correction: #113's 2026-10-18 triage supersedes its historic goja render-lock instructions. Native Vite/Kit owns development rendering; keep the retained browser behavior regression.

- correction: #330 reproduces as a returned Mutex.Unlock R_ADDROFF relocation error, not a demonstrated stuck loader. Session fallback only recognized CompleteBuild, leaving old literal HTTP 200 indefinitely after that error; promote failed native installation through that existing fallback and never reuse an acknowledgement stream after a timed-out read.
- decision: The exact #330 mutex relocation diagnostic is a returned installation error; no blocked loader call was established. Reuse the existing complete-build fallback on native install failure and reject late acknowledgements after a bounded/cancelled control exchange.
- decision: #113 edits while actual Go I/O is held, releases, then requests the changed route. Holding until a complete replacement host is ready is distinct #349 work; do not infer a universal in-flight generation guarantee from Kit's dev manifest.

- correction: http.Server.Shutdown returning at its deadline does not close active connections; explicit Server.Close must precede application cleanup. Keep application initialization and deferred cleanup in run, with main handling exit status only after run returns. A process-exit-only stream test can mask a missing Close; observe request-context cancellation before cleanup completes.
- decision: Generated server cleanup belongs in run(), before main translates errors to exit status. Go Shutdown returns ErrServerClosed from Serve immediately but must itself be awaited, and timeout does not close active connections; explicit server Close must precede application cleanup.

- correction: Kit 3.1.0 ordinary HttpError still invokes handleError; only already-handled bodies and redirects bypass it. Preserve an unexpected remote panic as an unknown error until the shared public policy runs, while keeping OnPanic reporting independent; reducing it to HTTPError first loses classification and the original private cause.

- correction: Remote HTTP envelopes do not cover Kit collect_remote_data during SSR. Assert the specific hydration query error entry, not merely a hook field elsewhere in the document. Single and batch SSR answers must record the transformed body and mark it handled before Svelte receives it, or a boundary runs the hook again.
- correction: #354 includes SSR-collected remote errors, not only endpoint envelopes: Kit collect_remote_data stores the full handled public error. Preserve extra fields in hydration and return handled envelopes to avoid invoking the application hook again at the component boundary.

- decision: #272 permits an explicit unavailable-capability error. The build bridge has Kit-to-Go callbacks but no Go-to-Kit fetch continuation; refuse known page/data/remote service destinations instead of fabricating missing 404s. Reuse endpoint routing's matcher/method/Accept selection so legitimate endpoint requests and fresh subrequest locals remain intact.

- correction: an explicitly selected application-config package is checked before generated helpers exist. Hook implementations in that package must use `skgo.RequestLocals[T]`, rather than the generated `LocalsFrom`, to remain bootstrappable.
- trap: Kit's HttpError/HandledHttpError stores public fields under `.body`; catching the object and reading `.message` directly renders empty text even when the remote hydration body is correct. Literal rendered text must be checked alongside the stored public body.
- correction: Kit may discard an unread fetch response when a header-policy check fails, ending its logical owner before background response cleanup. `/fetch-end` must tolerate an exchange already retired by its owner; unknown request owners still fail at `/fetch-begin`.
- correction: a HandleFetch rewrite changes the URL that owns a response cookie's default path. Build-time cookie relay must use each actual Kit continuation URL, before returning to the Go hook, rather than the original alias URL after the hook returns.
- correction: Build-time HandleFetch URL rewrites must relay each Kit continuation's cookies using the continued request URL before resuming Go. Using the original alias miscomputes default cookie paths; the nested-path real-build fixture reproduced and guards this.
- decision: Shared ApplicationConfig is explicitly selected by Go package/symbol; the generated prerender command retains registry ownership. Keep application hook policies in Go instead of appending duplicate JavaScript exports to generated hook-module test fixtures.
- friction: Two valid macOS test executables remained launched-suspended before the Go runtime, with zero CPU and dyld-only stacks. Their internal Go timeout cannot run; recover only the owned blocked processes and retry the affected packages, without changing global security settings.
- correction: Do not normalize an active captured log with an in-place editor. Renaming its inode detaches the writer and loses later completion records; wait for process exit before normalizing, and recheck only missing package receipts if this occurs.
