# Warm development supervisor

- decision: use pinned Kit3/Vite's existing `full-reload` and `error` payloads for Go readiness; Kit intentionally omits `path` because app.html is not the browser URL. Diagnostic documents need the real Vite client reachable while no Go application exists.
- correction: Gimbal owns a catalog lock, so overlapping old and replacement application processes is invalid. Compile first, then explicitly drain/stop-before-start for such applications. Ordinary applications can retain overlapping startup.
- friction: three producer worktrees changing during timings correctly invalidate captured source and produce fallback. Complete-source freezes are needed for controlled measurements, without interpreting concurrent-work numbers as performance regressions.
- decision: watcher identity uses source contents, not only size/mtime; equal-size timestamp-preserving writes must still invalidate. The per-request polling cost needs measuring before claiming fast browser latency.
- correction: first-ready suppression must use session settlement history, not presence of an old process; exclusive-resource handoff deliberately clears that process before successful settlement. The real TCP-lease test now also asserts the Vite reload notification.
- correction: SSE responses never drain naturally. Close tracked event streams when retiring an application so EventSource can reconnect, while finite assigned responses retain their drain guarantee; a held real SSE response now exercises exclusive handoff.
- measurement: the Go request benchmark with 768 source files (~6MiB) measured 12.38ms and 8.22MB allocations per request before digest reuse, versus 1.97ms and 0.85MB after. Reuse requires kernel change time plus inode, size and mtime; unsupported platforms reread bytes. Same-size timestamp-restored writes, atomic replacement and removal remain covered. A shell pipeline's ~80ms estimate was not the server's measured request overhead.
- correction: `/@vite/client` imports `@vite/env`, but Vite's own import analysis rewrites that dependency to its installed `env.mjs` URL. A standalone Go diagnostic page must forward that exact dependency too. The adapter now publishes it from the app's resolved Vite; the Go proxy allows exact bootstrap paths only. The adapter test runs installed Vite import analysis for root and nested bases, not only a mocked websocket.
- decision: development compilation defaults to `-ldflags=-w`, retaining the symbol table. `Debug` / `skgo dev --debug` restores Go's normal DWARF; explicit caller linker flags, including effective GOFLAGS, take precedence. Inspect actual child executables in tests: a live response alone cannot establish debugger availability. Internal linking is not a substitute because the separate Gimbal native-plugin experiment failed with that choice.
- correction: run frontend generation/build before the full test command, not concurrently: Go can embed the old manifest before the build finishes, correctly triggering the adapter identity and freshness guards. Regenerate checked-in registries after deterministic alias-order changes too.
- tooling: the installed `agent` CLI parses flags before its workdir; after-workdir `--session` becomes prompt text and starts a new session. Verify the actual native session, not merely the intended command, when resuming review.
- correction: the first main release qualification passed production and all 11 dev source-edit cases but failed two contact readiness steps. The dev trace had 111 module requests, no remote query yet, no JS error, and an import still pending at the five-second DOM assertion. The screenshot showed the real form and pending inbox. Wait for the existing Kit hydration marker before the unchanged inbox/form assertions, as the other form-ready steps already do; do not infer a query/data failure from a client that has not started it. The subsequent independent comparison found a new regression, not merely remaining #311 work: the prior main dev Chromium median was 2.7s (p90 4.2s), versus 7.3s (p90 8.9s) after the digest cache; production remained unchanged. The hydration prerequisite alone was insufficient to address that regression.

- correction: the digest cache mutex covered each complete repository walk, serializing concurrent browser module requests. Scans now use an immutable prior digest map and publish their own map under a short lock; fresh stat/ctime/inode verification remains per request, including after an older scan publishes last. A concurrent scan test fails if the first scan holds the cache lock; preserved-mtime and request-before-poll tests pass under race detection. The 768-file concurrent request benchmark improved from 1.96–2.03ms/op to 0.86–0.89ms/op locally; real browser qualification is still required because this throughput benchmark is not page latency.
- measurement: after removing scan serialization, the same-host full dev browser run passed 187/187 in 3.2m versus 5.1m before; HTML report Chromium median 7.767→3.332s, p90 9.745→5.068s, contact cases 6.296/5.965→2.504/2.269s. Parse the report JSON rather than rounded console durations: fast scenarios may print milliseconds and disappear from a seconds-only grep. Independent R2 ran the full dev race suite and verified both lock and missing-ctime mutations fail; only nitpicks remained. Main qualification still decides publication.
