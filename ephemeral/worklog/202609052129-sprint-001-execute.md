# Sprint 001 execution — actionable intelligence

## Corrections to the sprint doc

**`builder.writeJson` does not exist in kit 3.0.0-next.25.** The adapter sketch in
SPRINT-001.md §"Build output" calls it. The `Builder` interface
(`reference/kit/packages/kit/types/index.d.ts:L104-L230`) and its implementation
(`src/core/adapt/builder.js`) expose only `copy`, `writeClient`, `writePrerendered`,
`writeServer`, `generateFallback`, `generateEnvModule`, `generateManifest`,
`getBuildDirectory`/`getClientDirectory`/`getServerDirectory`/`getAppPath`,
`findServerAssets`, `compress`, `instrument`, `hasServerInstrumentationFile`,
plus deprecated `rimraf`/`mkdirp`. `skgo-adapter.js` writes the manifest with
`node:fs` instead. `rimraf`/`mkdirp` are marked `@deprecated` on the 3.0 line, so the
adapter uses `fs.rmSync` directly too.

**`builder.writePrerendered` is safe with no prerendered output.** `copy()` returns `[]`
when the source is missing (`src/utils/filesystem.js:L15`), so the call is a no-op and
`build/prerendered/` is simply never created.

## Deviations

**`NewDevProxy` takes a logger.** Signature is
`NewDevProxy(target *url.URL, logf func(string, ...any)) http.Handler`, not the
one-argument form in the sprint doc. The doc's own dev check requires observing the
WebSocket upgrade *at Go's port* to rule out Vite's direct-to-5173 fallback; a proxy
that cannot say so makes that check impossible. `proxy_test.go` asserts the line is
emitted for a real 101 tunnel.

**`go test ./...` from the root does NOT cover `example/`.** The sprint doc's Phase 6
says "workspace covers `example/`"; it does not. A `go.work` makes cross-module
*resolution* work (`go build ./example/cmd` from the root succeeds), but `./...`
still expands only within the current module — `go list ./...` at the root prints
one package. The gate command is `go test ./... ./example/...` (same for `go vet`).

## Traps hit during execution

**`vp dev` only runs SvelteKit 3 from the project-local Vite+ with `vite` aliased.**
`mise x -- vp dev` dies with "The configured Vite SSR environment must be a
RunnableDevEnvironment" (`@sveltejs/kit/src/runner.js:9`). Kit's check is
`vite.isRunnableDevEnvironment(server.environments.ssr)`, an `instanceof` against the
`vite` module *kit* resolved, while the mise-global `vp` creates the server from the
copy it bundles under `~/.local/share/mise/installs/npm-vite-plus/0.3.0/`. Two
instances of the same version, so the check can never pass. The junkyard oracle had
already solved this (`junkyard/ephemeral/worklog/20260904-remote-oracle-or1.md`, line 4):
`"vite": "npm:@voidzero-dev/vite-plus-core@0.3.0"` plus `"vite-plus": "0.3.0"` in
devDependencies, `defineConfig` imported from `vite-plus`, and the dev server launched as
`node_modules/.bin/vp dev`. Aliasing alone is not enough — a reviewer proved the alias
with the mise-global `vp` still fails — the binary must be the project-local one so kit
and Vite+ share a single module instance. `vp install`/`vp build` work through either.

**Reviewers who read only `runtime/props.svelte.js` conclude pages get no `params`
prop.** They do: `runtime/components/root.svelte` renders every page as
`<Component {data} {form} params={page.params}>` and the generated `PageProps` type is
`{ params, data, form }`. `let { params }: PageProps = $props()` is the intended shape.

**Air's `root` does not change its working directory.** The sprint doc's `.air.toml`
uses `root = ".."` with `cmd = "cd example && go build …"` and
`bin = "example/tmp/skgo-example"`. `root` only scopes the *watcher*; `cmd` runs, and
`bin` resolves, in the directory Air was launched from (`example/`, per the Procfile),
producing `cd: example: No such file or directory` and then
`example/example/tmp/skgo-example: No such file or directory`. `cmd` and `bin` are now
relative to `example/`; `tmp_dir` and `exclude_dir` stay relative to `root`.

**Air ignores `touch`.** Only content writes trigger a rebuild, so `touch proxy.go`
proves nothing about the dev loop; append to the file instead.

**A WebSocket client that never fetches modules sees no HMR update.** Holding a raw
`vite-hmr` socket open through Go and editing `Greeting.svelte` yields only
`{"type":"connected"}` — Vite computes updates from its module graph, which is empty
until a client actually requests the modules. The hot-update proof needs a real browser.

**playwright-bdd 9.2.0 custom fixtures must extend `test` from `playwright-bdd`,
not from `@playwright/test`.** `createBdd(test)` throws
"createBdd() should use 'test' extended from \"playwright-bdd\"" otherwise.
`importTestFrom` is no longer needed — the fixtures file just has to be inside the
`steps` glob (the package warns if you pass it).

**`@types/node` is required in `example/e2e`.** Without it `tsc -p tsconfig.json`
fails with TS2688 for the `node` type library used by `process.env` and
`import.meta.url`. `pnpm-workspace.yaml` needs the same `minimumReleaseAgeExclude`
entry as `example/web`.
