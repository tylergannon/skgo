## Reporter selection, options and module context

The native effective list is:

```text
base = nonempty last CLI --reporter value resolved as CSV
       otherwise resolved config.reporter
       otherwise [[CI ? 'dot' : 'list']]
effective = base followed by resolved nonempty last --add-reporter CSV
```

Here “nonempty” describes `resolveReporterOption`, not absence of an operand. Commander rejects a missing required operand before this formula applies. It overwrites repeated scalar flags, so the last `--reporter`, `--add-reporter` and `--config` value wins independently. These flags do not accumulate with repetition. CSV order and configuration tuple order remain intact; neither resolver trims or deduplicates IDs. `--reporter=json,json` deliberately selects two instances, whereas `--reporter=list --reporter=json` selects only JSON. The wrapper must not merge those semantics. [S1–S3, S5]

Configuration accepts a reporter string or an array of tuples `[id]` / `[id, options]`. A config string is one ID, not CSV: `reporter: 'list,json'` attempts to resolve that literal module ID. The empty config string yields the native default; an empty array selects no configured reporters. Config tuples preserve their options. `createReporters` passes `{...nativeCommandOptions, ...tupleOptions}` to each constructor; it does not replace tuples with bare IDs. JSON's public option is `outputFile`; HTML includes `outputFolder` and `open`; blob includes `outputDir` and `fileName`. Other public options and custom reporter option objects must survive unchanged when their configured reporter is selected. [S3, S6, S8]

An explicit nonempty CLI replacement intentionally removes the configured list/options. An addition appends after that replacement or after the configured/default base. Thus config HTML+JSON options plus `--add-reporter=list` is a different case from `--reporter=html,json,list`. An empty CLI replacement falls back to config; it must not erase config tuple options. Config validation/resolution is still native work: its expression resolves config reporters even when a CLI replacement is present, so an invalid configured custom module can still fail a native run. [S2–S4]

Module context is also part of selection:

- CLI IDs matching built-ins exactly remain built-ins. Other CLI IDs first try the existing `path.resolve(cwd, id)`, then `require.resolve(id, {paths: [cwd]})`. Test and merge implement the same CLI rule. Relative CLI paths therefore use the invocation working directory, not configDir. [S2, S4]
- Config non-built-in IDs use `require.resolve(id, {paths: [configDir]})`. A config in another directory must retain its own relative modules/package resolution and tuple options, even when the CLI also appends a module rooted in cwd. [S3]
- Native built-ins are `list,line,dot,json,junit,null,github,html,blob,perfetto`. Preserve native choices rather than introducing a wrapper-only whitelist. Compatibility controls concentrate on repository list+HTML, requested JSON, internal blob, and module/composition forwarding; they do not implement or exhaustively retest each reporter's own rendering. [S3, S8]

**Correction boundary:** `merge-reports` accepts replacement `--reporter`, but has no `--add-reporter`. Passing a combined bare CSV can express CLI replacement+addition; it cannot express configured tuple options+addition. A successful final merge that silently drops an addition or tuple options does not satisfy the contract. Reading arbitrary TS/JS config as a Go string, or maintaining a skgo JavaScript reporter harness, is not authorized by this survey.

### Caller-selected bounded support

After this survey's source check, the caller explicitly selected the following scope for the correction. These are wrapper limits; they must not be described as all of native Playwright's supported combinations:

- Use **one native merge and one multiplexer**. With an explicit nonempty CLI replacement, combine its CSV with the last nonempty added CSV in order and delegate all IDs, package resolution and duplicates to native `--reporter`. Config reporter modules still undergo native config loading/validation.
- With configured/default base (including an explicit empty CLI replacement), support **one** added built-in or existing cwd-local/absolute reporter path. Preserve base tuples/options; resolve an existing CLI-local path to absolute, then use native `PW_TEST_REPORTER` only on the final merge. Native `loadReporter` resolves a non-built-in hook value against **config.config.rootDir**, not cwd or configDir, so an unresolved relative CLI path is wrong. It does not perform the CLI `require.resolve(packageID, {paths:[cwd]})` step. An existing local path must therefore be absolute; a bare package-module addition is explicitly unsupported in this branch.
- Configured/default base plus multiple added IDs or a bare package-module addition must return an explicit nonzero unsupported-compatibility error. No drop/success, deduplication or claim of native equivalence. Existing configured package reporters and explicit CLI replacement package reporters remain delegated to native resolution.
- Go itself follows native reporter selection: destination env alone does not select JSON. Preserve the authorized root `just e2e` convenience by explicitly adding `--add-reporter=json` in the root recipe for nonempty JSON FILE/NAME. That preserves selected base options in the same multiplexer. Direct VP callers select reporters explicitly. DIR-only/empty FILE+NAME do not trigger this root addition.
- Reject nonempty caller `PW_TEST_REPORTER` up front as incompatible with exclusive stage blobs; the wrapper owns its internal final-hook value. Override valid caller project selections with fixed stage sets, but reject missing/empty operands and retain pinned native operand arity. Retire legacy initial-separator normalization and preserve the actual standalone native separator.

These bounds cover required JSON/root/site usage without the two-merge defect. The broader native mapping remains useful as the authority for explicitly rejected combinations. A required operand literally equal to `--` also needs an explicit disposition: the bounded recommendation is a nonzero unsupported error, while an ordinary standalone separator remains supported. This is a wrapper compatibility limit, **not** a native missing-operand error; the native counterexample below shows why it cannot be casually rewritten.

## CLI operands and option boundaries

| Option/case | Native 1.63 spelling and semantics | Wrapper obligation |
| --- | --- | --- |
| Replacement | `--reporter VALUE`, `--reporter=VALUE`; required scalar, CSV. | Preserve last selection for the final report; remove it from owned stages only after correct parsing/validation. |
| Addition | `--add-reporter VALUE`, `--add-reporter=VALUE`; required scalar, CSV. | Preserve last addition and base options on final reporting; no added reporter may write a stage-only final report. |
| Config | `-c VALUE`, `-cVALUE`, `--config VALUE`, `--config=VALUE`; required scalar, last wins. | Use the same selected config for tests and reporting, resolving relative paths from the same cwd. `-c=VALUE` supplies literal `=VALUE`; it is not the long-option delimiter. |
| Project | `--project VALUE...`, repeated separated flags, or repeated `--project=VALUE`; required variadic. | Wrapper intentionally replaces caller project selection with its ordered stage sets, but must consume native operand boundaries without converting names into file filters or discarding syntax errors. |
| Separated variadic | `--project chromium noscript --grep literal` consumes both names. | Both names belong to the owned selection; neither becomes a positional filter. |
| Equals variadic | `--project=chromium noscript` consumes only `chromium`; the parser's equals branch does not activate continued variadic consumption. `noscript` is a positional file filter. | Preserve this distinction. Do not consume subsequent bare values as names in the equals form. |
| Unsupported aliases | Reporter `-r`, `-rjson`, `-r=json`; project `-p`, `-p=chromium`, `-pchromium`; unregistered long abbreviations. | Native declares no reporter/project short alias. Do not strip them into a successful run or certify existing mock tests that accept them. Native unknown-option failure must remain nonzero. |
| Missing required operand | Bare `--reporter`, `--add-reporter`, `--config`, `-c`, `--project` at end of argv. | Nonzero native parse failure; an injected owned flag must not accidentally become the missing user operand. Validate before discarding these tokens. |
| Explicit empty reporter | `--reporter=` or `--reporter ''`. | Native empty value means no CLI override: retain configured/default base, unlike a missing operand. |
| Explicit empty addition | `--add-reporter=` or `--add-reporter ''`. | No added reporters; unlike a missing operand. Last empty addition clears an earlier scalar addition. |
| Explicit empty config | `--config=` / `--config ''` / `-c ''`. | Native uses cwd discovery, unlike a missing operand. Last empty config returns to cwd. |
| Explicit empty project | `--project=` / `--project ''`. | This is a supplied empty name, not a missing operand. Native filtering can match an empty-named project; with the required three named wrapper projects it produces an unknown-project error. Do not silently turn that fixture's native error into success. |
| Flag-looking required value | E.g. `--grep '--reporter=json'` or `--grep '--config=/other'`. | Commander consumes the next token as the required value even if it looks like a flag. The wrapper must not scan inside that value as reporter/config selection. Likewise, do not universally declare a next token beginning `-` to be a missing operand. |
| Token after `--` | Commander stops option parsing and returns trailing tokens as operands; the Playwright test action explicitly removes post-`--` tokens from its **test filters**. | No reporter/config/project extraction after this boundary. Do not describe trailing tokens as ordinary native file filters. |

These expectations are source-backed by S1, S2, S4, S5 and S10. Most operand/repetition partitions lack a retained execution and are explicitly pending in the control matrix below. Unknown/empty reporter entries in a nonempty CSV are resolved as module IDs, not trimmed away: `list, json` and `json,` need native failure controls in a fixture with no such valid modules. Config errors, module resolution/load errors and parser errors must not become a green wrapper result.

The wrapper's current leading-`--` removal is a separate legacy forwarding normalization. Canonical VP forwards arguments after the task name directly and needs no separator; the fixed root recipe no longer offers variadic arguments. There is no native authority for treating `wrapper -- --reporter=json` as equivalent to `playwright test -- --reporter=json`. The caller-selected correction retires that normalization. An **internal** standalone `--` remains the native boundary: no project/reporter/config token after it may be stripped or interpreted. Native test action finds the first literal `--` in raw `process.argv`, independently of Commander parsing, including a token consumed as a required value. [S1, S5, S10, S11]

The exact action applies `parsedPositionalArgs.slice(0, parsedPositionalArgs.length - rawPostDashCount)`, with JavaScript's normal negative-end slice semantics. Owned flag injection/removal can change that raw count even if the literal `--` was an option value. The actual R8 boundary control uses three file operands and `--grep '--'`: native `--list` lists all three files, but appending one redundant `--reporter=json` makes it list only the first two. Therefore treating a consumed literal `--` as a standalone separator, or simply retaining that value while changing the suffix, does not preserve native file selection. Explicitly rejecting this exotic required-value case is the proposed bounded handling; reproducing the raw formula would require separate proof and is not needed for the authorized root/site invocation.

The wrapper owns only stage project choice, stage run labels, private reporting transport and final aggregate reporting. Positional file regexes before the native separator, `--grep`/`-g`, `--grep-invert`/`-G`, their literal quoting, and other native test options retain native meaning in both stages. Caller project filters cannot move source-edit into the regular stage or expand regular projects into the mutation stage. Unknown caller project-name selection is an intentional ownership exception only if recorded as such; it must not be confused with native acceptance of unknown names. Native defaults such as `--pass-with-no-tests` and `--list` can intentionally alter collected/executed results; a no-test run is not proof that browser scenarios executed. Interactive UI/debug/watch modes are not qualified by this batch reporting survey.

## Selected reporter destinations and environment precedence

The environment does **not** select native JSON/HTML/blob/JUnit/Perfetto reporters. Selection happens above; a selected constructor reads its environment. The current Go wrapper additionally treats nonempty JSON FILE/NAME as a request for JSON. That is an existing convenience, evidenced by its tests and retained env-only reports, not native `--reporter` replacement authority. The caller-selected correction relocates this convenience to the root recipe's explicit addition; Go/direct VP follow native selection. Retain configured JSON options and the other selected base reporters when the root adds JSON. [S2, S3, S7, S10]

For `R = JSON, BLOB, JUNIT, PERFETTO`, native `resolveOutputFile(R, options)` follows this exact order [S6]:

1. Nonempty `PLAYWRIGHT_R_OUTPUT_FILE`, resolved from **cwd**, wins immediately.
2. Otherwise truthy `options.outputFile`, resolved from **configDir**, wins immediately. Lower-priority DIR/NAME values are not consulted.
3. Otherwise choose directory: nonempty env OUTPUT_DIR resolved from **cwd**, then truthy configured `outputDir` resolved from **configDir**, then the reporter's default directory, then **configDir**.
4. Choose filename with **nullish**, not truthy, fallback: env OUTPUT_NAME `??` configured `fileName` `??` reporter default filename. If the chosen name is falsy, the helper returns `undefined`; otherwise `path.resolve(directory, name)` produces the file. An absolute NAME overrides the chosen directory.

Empty FILE/DIR strings are ignored by the env helper. An explicitly empty NAME is present for `??`, suppresses filename fallback, and yields no resolved output when no higher-priority file exists. JSON/JUnit then emit stdout; blob/Perfetto expect a resolved file and do not gain a documented stdout mode from this case. The exact native failure for their empty-name case is not retained and needs a negative control if those callers are qualified. Configured/default generic `outputDir`/`fileName` handling exists in the implementation; JSON's public typed option remains `outputFile`, not a newly designed directory API.

| Selected reporter | Destination/default and additional native behavior |
| --- | --- |
| JSON | Without a resolved file, native JSON is pretty-printed to stdout. With a file, parent directories are created and that file is written. Config `outputFile` wins over env DIR/NAME; env FILE wins over config `outputFile`. DIR alone supplies no JSON filename and does not create a native JSON file or select JSON. |
| Blob | Public options `outputDir`,`fileName`; default filename `report[-commandHash][-shard].zip`, default directory `blob-report`. Native default directory is the nearest package.json directory above configDir, or cwd if none. Configured `fileName` must end in `.zip`. Native preparation clears its output directory unless its internal preservation env is set. Internal stage paths must therefore be isolated from each other and from caller blob settings. |
| HTML | Nonempty `PLAYWRIGHT_HTML_OUTPUT_DIR` wins, then legacy `PLAYWRIGHT_HTML_REPORT`; both resolve from cwd. Otherwise truthy `outputFolder` resolves from configDir; default `playwright-report` uses the package-root rule above. Native `PLAYWRIGHT_HTML_OPEN` / legacy `PW_TEST_HTML_REPORT_OPEN` precede configured `open`, then `on-failure`; native validates the values and diagnoses invalid ones. Preserve configured `open: 'never'` and the caller's env on the final report. HTML clears its output directory; retained JSON resource paths must not be stored inside a folder it clears. |
| JUnit / Perfetto | Same shared FILE/config-FILE/DIR/NAME resolution; JUnit defaults to stdout, Perfetto defaults to `test-results/perfetto.json` under the package-root rule. HTML additionally resolves attachmentsBaseURL, host, port and title from its native env/options, and boolean HTML switches use native parsing (`false`/`0` false, another nonempty string true, absent/empty fallback). JUnit's native env booleans likewise remain native work. No wrapper reimplementation is needed; preserving option objects and final environment covers these settings. Native `PW_TEST_REPORTER` is an internal extra-reporter hook applied by `createReporters`, distinct from public `--add-reporter`. It can defeat exclusive stage reporter ownership if inherited. R8 exercises the native final hook with JSON; the caller-selected wrapper policy rejects inherited nonempty values, clears it from stages and owns only the bounded final addition. Custom-path/package limits are stated above. [S7, S8]

**Destination correction obligation:** do not predelete or stale-check a lower-priority env NAME path as if it were the configured JSON destination. The actual configured file can otherwise remain stale while a wrong file is created. Conversely, an explicit caller `--reporter=json` intentionally discards configured `outputFile`, so env NAME then legitimately applies. Those two triggers require separate controls.

## Ordered blobs and final native output

Each stage must record only its private native blob transport. Its own absolute FILE/DIR and isolated stage directory must override caller BLOB FILE/DIR/NAME; final reporter selection/additions and destination-writing hooks must not produce per-stage JSON/HTML/JUnit files. The first stage cannot clear the second's blob directory, and no shared default blob directory may lose a completed stage. Source-edit still runs after a normal failed regular result. External cancellation is a separate early-stop case. [S7, S10]

Final reporting uses the caller's selected/discovered config, unchanged reporter options/context and original final reporter environment. Native test discovery without `-c` looks in cwd, but native merge without `-c` loads an empty config; preserving the former requires explicitly carrying its config discovery into merge. A selected config directory discovers `.ts,.js,.mts,.mjs,.cts,.cjs` in that order; a selected file uses its parent as configDir; nonexistent locations fail. The same cwd is needed for relative CLI module/env destinations. [S4]

Only fresh blobs from this run are merged. Native merge sorts/validates blobs, checks metadata/version, patches identities and workers, replays errors/stdout/stderr/results and owns suite/stat serialization. It does not perform the former handwritten JSON concatenation. Its end status precedence is failed, timedout, interrupted, passed; timing spans earliest start to latest finish, **not the sum of stage durations**. Native JSON retains global `errors`, outcome counters, literal test result/error data, steps/stdout/stderr and attachments. Body attachments remain base64; existing file attachments are packed into native resources and rewritten to absolute retained resource paths. Keep those resources available after merge and after scratch cleanup. Do not “fix” a missing attachment by fabricating bytes. [S7–S9]

Native reporter order matters. JSON-only stdout has one parseable document; stage diagnostics must stay outside that stdout. An explicit `list,json` composition has native list text plus one complete JSON document on stdout, so whole-stdout JSON parsing is the wrong assertion. A duplicate `json,json` selection creates two native instances and may print two full documents; deduplicating it silently changes native selection. A file JSON report may coexist with native merge progress on stdout. “One complete report” means the selected JSON instance receives both stages, not that the wrapper erases explicitly selected native reporter output. [S7–S9]

Native `merge-reports` exits 1 for merge/reporter errors; it can exit 0 while replaying failed tests. The wrapper must retain each original stage failure independently of successful reporting. Missing/corrupt blobs, config/module/report-write failures and merge errors remain nonzero. A successful merged file alone is not a successful test run. Cancellation remains distinguishable from ordinary failure and must stop later source-edit/merge work; it must not turn an incomplete prior report into a completed run. [S2, S4, S8–S10]

### Observed reporter-error and listing policy

The apparent swallowed-exception ambiguity is resolved by both source and R8 actual executions. Multiplexer `_wrap` / `_wrapAsync` **catch without rethrowing**, set `_hasReporterErrors=true`, and normally redispatch the serialized error through `onError`. Test `finishTaskRun` changes a still-passed result to failed after `onEnd`/`onExit` when that flag is set; native merge returns failed from the same flag; their CLI actions exit 1. Constructor/module-load errors occur outside that callback catch and reach the CLI error path. Thus swallowing the callback exception does not imply a zero CLI exit in the observed cases. It also does not guarantee an exception is printed to stderr or included in an already-written JSON report.

Actual native **test and merge** controls give:

| Trigger | Exact native result |
| --- | --- |
| Authored constructor throws `literal-constructor-failure-42` | Both exit **1**, print a stack to stderr, execute no new test bodies and leave the seeded JSON sentinel untouched. Native does not remove a previous report merely because a reporter constructor failed. |
| Authored synchronous/async `onEnd` throws **after** a file JSON reporter | Both exit **1**. File JSON already contains **3 expected,0 skipped/unexpected/flaky, errors=[]**. Test stdout prints the callback failure after `3 passed`; merge stdout contains only merge progress and stderr is empty. No blanket requirement that the final JSON `errors` include a later reporter callback exception is source-faithful. |
| Authored `onEnd` throws **before** the added JSON reporter in the same native merge | Exit **1**, standalone stdout JSON retains all 3 passing results and contains the literal callback error in `errors`. Callback order determines whether JSON has seen this error at serialization time. |

## Bounded correction obligations and remaining uncertainty

1. Parse only actual native reporter/config/project flags with their actual operand boundaries, repeat/empty semantics and end-of-options handling. Required-value validation must precede removal/injection. Preserve other options and values; do not accept invented short aliases. Keep ownership of the ordered project sets explicit.
2. Preserve the supported native reporter list, order, module context and tuple options through **one** final multiplexer, including additions within the caller-selected bounds. Reject unsupported native combinations explicitly. Internal stages must not emit the caller's requested final outputs. Native merge lacks an addition flag; a CSV-only solution must not silently drop configured options, and two merges cannot preserve one pipeline's stdout/error behavior.
3. Delegate destination/report construction to the installed native implementation. Preserve FILE > configured outputFile > DIR/NAME resolution and distinguish unset/empty env values. Relocate env-only JSON convenience to the root recipe's explicit addition; Go/native selection must not accidentally act as explicit reporter replacement or predelete the wrong path.
4. Keep private fresh blob directories and retained native resources, pass the right config context to merge, and retain aggregate original stage failures separately from native merge success. Continue source-edit after ordinary regular failure; stop on explicit cancellation.
5. Prove the finite new partitions with native controls and saved stdout/stderr/file/exit outputs, then run the corrected canonical root modes and appropriate Go checks. Reuse each expensive captured run for counts, errors, skips, literal contents, destinations and attachment assertions. No dependency rework, Go/SSR change or new maintained JavaScript/shell acceptance harness is implied.
