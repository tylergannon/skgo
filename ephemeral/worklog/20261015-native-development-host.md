# Native development host integration

- discovery: A whole-module `./...` scan includes production main packages and their build embeds; these are not the executable served by the private development host. Native admission must cover the constructor's executable import closure, including every reverse caller, while discovering constructors independently.
- discovery: Actual example has generic route helpers. Lower's CompleteBuild means an unsupported native package, not an application that cannot start. Leave that package ordinary compiled Go and rebuild when it changes.
- defect: Calling upstream loader.RegSymbol separately for every instrumented route overflowed its fixed `[64]uintptr` function-pointer slots on the second package: `panic: runtime error: index out of range [64] with length 64`, at `link.getFuncPointer` through `addIfaceLinkName` and `SkgoHotInit`. A generated host must register its executable once and initialize private package symbol copies from that registration. The real HTTP host test now has two independent instrumented packages.
- trap: CompilerInputs includes both authored colocated route copies and their generated importable link copies. AuthoredPath alone collapses them. Rebase using authored identity plus module-relative compiler location, then treat the authored mirror as the corresponding generated package, rather than demanding rebuild for every body edit.
- boundary: Existing application NewHandler composes app-specific hooks and middleware. Replacing it with a generated default stack silently loses behavior. Native host invokes the real constructor and privately augments only the FetchConfig context seam; existing custom context carry is composed.
