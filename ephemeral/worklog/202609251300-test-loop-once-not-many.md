finding: The 15s `just test` budget can't be reached by restructuring tests alone. One `go generate` (or a valid `gen.Check`) of the example starts about 130 `go list` processes (around 43 `packages.Load`, most of them polytype's `grammar.Load`, one per type-set directory). That is about 5s of wall clock and 7.5 core-seconds even at GOMAXPROCS=2. internal/gen needs several of these passes for claims that really are distinct. The next lever is batching those loads inside the generator, which is a product change and not a test change.
finding: This machine runs about 2.2 generator passes at once. Four concurrent passes take 9s against 5s for one. Adding test parallelism past that point buys nothing, and the whole suite is CPU-bound (about 280 core-seconds).
finding: A Go child process running at the default GOMAXPROCS spends most of its CPU in the kernel on idle Ps. One `skgo generate` measured 21s of system time at the default and 4s at 2, with the same wall clock. Setting `GOMAXPROCS=2` in TestMain for child processes cut about 45 core-seconds from the full suite.
trap: `go test` puts GOROOT/bin first on PATH for the processes it starts, so a `go` shim placed first on PATH never sees the go calls made from inside tests. To trace them, compile the test binary with `go test -c` and run it with the shim on PATH.
trap: A fresh sandbox directory starts with a cold build cache, because the go command puts the package directory in the action ID. `skgo check` over a fresh copy of the example costs about 14 core-seconds; over a copy it has already checked, about 5.7. Reuse one copy for a sequence of CLI runs, and restore what each run changed.
trap: A test blocked on a shared fixture still holds one of the `-parallel` slots (10 here). Heavy fixture work started from `t.Parallel` subtests queued behind them. Start that work from a goroutine inside the fixture.
trap: A `polytype.Nullable` field in a Form input removes that Form from the generated Go client (`clientForm`). Don't plant one on a Form whose client other tests assert on.
