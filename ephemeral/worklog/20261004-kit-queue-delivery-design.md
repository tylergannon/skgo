## Consumer configuration, without editing installed packages

Add Go command `go tool skgo kit-patch --web web --apply` and read-only `--check`; exactly one action is required. `--apply` configures project files only, prints that installation is still required, and never claims installed compatibility. Existing-consumer contract after matching Go/adapter upgrade:

    go tool skgo kit-patch --web web --apply
    cd web && node_modules/.bin/vp install --no-frozen-lockfile
    go tool skgo kit-patch --web web --check

The last command is run from the Go app root (the cd above is a separate user shell step). Subsequent clean/CI installs use ordinary VP/just frozen install, with the committed patch/config/lockfile. The packaged SDK supplies the patch; consumers do not download an unpublished gist or copy from this worktree. A missing local VP must be reported as a tool/bootstrap requirement, never skipped.

`--web` resolves the selected app's package.json. For the usual standalone generated frontend, workspace root is web. If a nearer actual pnpm-workspace.yaml is above web, require an explicit `--workspace ROOT` matching that nearest workspace rather than silently modifying a parent workspace. Reject an explicitly mismatching root. Print the selected root and all files the apply action will modify. Project-level pnpm patchedDependencies intentionally affects all exact Kit3.0.0 instances in that selected workspace; explain this scope in CLI output for an explicitly selected shared workspace. No global configuration writes, hooks, postinstall scripts, or startup mutation.

Preflight before any authored file mutation: package manifest valid; Kit dependency exists in exactly one dependency section; currently installed Kit, if present, has exact name/version and stock or corrected queue hash; canonical payload/metadata hashes match; patch destination absent or byte-identical; project patch configuration has no conflicting exact/wildcard/range entry that would match Kit3.0.0. Other package patches remain unchanged. Reject unexpected source/version or existing incompatible Kit patches before any write; do not overwrite or silently compose them.

Pin only this app's existing @sveltejs/kit dependency entry to exact 3.0.0, preserving its dependency section and every other manifest value. Catalog/range declarations become a direct exact entry; unrelated catalog entries are untouched. Copy the canonical patch into WORKSPACE/patches/skgo-kit-3.0.0-queue.patch with atomic replacement/no different-file overwrite. Use native pnpm12.9.1 config get/set from exactly WORKSPACE, always --location=project and --json, to preserve/merge the patchedDependencies map. New exact entry:

    @sveltejs/kit@3.0.0: patches/skgo-kit-3.0.0-queue.patch

Native pnpm owns YAML serialization. Go never hand-edits pnpm-lock.yaml. No allow-unused/nonapplied-patch setting, --force, integrity bypass, or broad override is added. Native VP install applies the checked-in diff and writes its ordinary patched dependency hash/integrity to the lockfile. Native installation failure is nonzero; keep authored configuration reviewable for retry. Successful configuration is idempotent. Preserve unrelated configuration fields. Test native pnpm12.9.1 actual get/set behavior instead of assuming document examples cover it.

`--check` verifies the selected project has the exact entry, canonical file/hash, exact direct Kit pin, and actual resolved installed package name/version/corrected queue hash. It fails when configured-but-not-installed, unpatched, mismatching, missing, or conflicting. The helper does not pretend a metadata entry proves installed bytes.

## Removal condition

Carry the patch only for exact Kit3.0.0. No catch-all version acceptance or semantic source-pattern probing. Remove the temporary correction in an SKGO release only after a released upstream version passes unchanged async-idle-gap, noarg-only, same-export, producer/body-overlap, early native failure, and cancellation controls. That release supplies an explicit migration to drop only the owned exact patchedDependencies entry/file, update the Kit pin and native lockfile, and verify the new stock source. Do not auto-remove or apply this patch to an unknown newer version. No upstream communication is currently authorized.

## Native pnpm raw-map amendment (2026-10-04)

Actual native pnpm12.9.1 get/list/property-path reads resolve relative patchedDependencies to absolute paths. The official config command documentation explicitly states set does not accept property paths. The original no-parser get/merge/set assumption is therefore withdrawn: resolution-equivalent values do not prove preservation of authored values. The observed example getter maps the authored `patches/skgo-kit-3.0.0-queue.patch` to an absolute checkout path.

The bounded Go installer may add only the already-checksummed `gopkg.in/yaml.v3 v3.0.1` direct requirement. It reads the selected regular workspace file with the proper decoder; it must never use a YAML encoder/marshal operation, hand-written line scanning, or author the lockfile. Decode generic YAML values so numeric/bool/null patch keys or paths cannot be silently coerced into strings; validate root/patch-map shape and require literal string keys/values. Default duplicate-key checks remain enabled. Decode exactly one document, then require EOF. Missing workspace/map can represent an empty project map; malformed, nonmapping or unsupported values must refuse before writes. Anchors, merges, flow maps and quoted strings are handled by the library and compared with actual native pnpm output. No interpolation is invented.

Read the raw selected-project map and native getter map separately. Require identical keys and agreement between each raw path resolved from the selected root and the getter's normalized path. A global/env/source ambiguity or native/parser disagreement refuses before any authored write. Configure adds only the canonical portable relative owned entry to the raw map and delegates its serialization to native pnpm config set. Verify requires the raw portable owned entry, actual canonical patch bytes, direct Kit pin, native resolved-map agreement and corrected physical installed queue hash. Existing unrelated relative and absolute path strings must retain their authored logical values after set.

Worker B ownership expands only to the one pinned go.mod requirement (and go.sum only if the Go tool genuinely needs it). No unrelated module update. Required real pnpm controls include literal unrelated relative and absolute values after serialization, flow/quoted/comment/alias/merge inputs, duplicate root/patch keys, malformed shape/scalar values and multiple documents, idempotence and all existing no-write/conflict/parent refusal checks. A one-line dependency/read-parser amendment is necessary for the requested consumer preservation behavior; it does not authorize broader dependency work.

This amendment was planned by Sol and reviewed against existing yaml.v3 decoder source by Astra before Luna implementation. Its integrated product and native consumer proof remain required. Parent-workspace mutation remains prohibited; a selected frontend with its own existing regular workspace file may be changed without altering an ancestor, while a nearest workspace above a frontend lacking its own must refuse rather than create a nested bypass.
