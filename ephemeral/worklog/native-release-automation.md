# Native release automation

decision: Native versions are reserved with immutable `plugins/native-shell/vX.Y.Z` tags before building. Pending/failed candidates consume versions; gaps are safe and prevent concurrent candidates from receiving the same version.
decision: The core Release publishes a public identity artifact only after publication succeeds. Native workflow_run consumers read this artifact, verify its run and published tag, and build against the downloaded official executable. Plugin source identity remains distinct from the core tag identity.
decision: Qualification promotes the original run-attempt artifact, including its manifest, checksum and release notes. A rerun reuses an existing uploaded candidate instead of recompiling it.
friction: Installed actionlint 1.7.12 does not understand GitHub's existing queue:max concurrency extension. Validate both changed workflows with only that line removed in stdin and the repository runner-label configuration; all remaining workflow/shell checks pass.
decision: Candidate build and dispatch are separate jobs. A failed dispatch rerun can promote the original successful build attempt after the latest overall run succeeds; requiring the original whole attempt to succeed would make immutable bytes unrecoverable after a transient notification failure.
decision: Freeze core Go/VitePlus/PNPM declarations and exact Node pin from the selected core commit, plus Zig/XcodeGen from the native source commit. Candidate toolchain metadata and generated notes travel with the original archive, avoiding stale frontend pins when core upgrades.
correction: Independent review rejected stranding explicit versions after pre-upload failure. Reservations now use annotated tags containing the owning run identity; only that run can resume an unpublished reservation. Concurrent or unrelated requests still cannot replace the tag.
correction: A successful core publish=false runner qualification should produce no native failure. A Linux eligibility job checks the upstream publishing job and skips macOS work for dry runs; a purported publishing success without identity still fails closed.
decision: Publication persists release.json with the full original request identity and toolchain SHA256. Published-only recovery verifies the permanent receipt, tag/source/core identity, candidate manifest, toolchain bytes and plugin checksum without depending on an expiring Actions artifact. Incoming promotion still requires the original archive and passed candidate.
correction: Generated notes claim macOS ARM64 only. A macOS14 deployment-target setting is not evidence that linked SDK objects work on macOS14, so no minimum-OS qualification is advertised.
friction: Verbatim consumer recipe execution found mise exec exporting pinned GOROOT while updater children selected Homebrew's newer Go from ambient PATH. Explicit pinned executable directories and GOTOOLCHAIN fix child compiler selection.
friction: mise/npm-installed vite-plus is the local CLI and rejects updater `toolchain --global`. Use an isolated official global VP_HOME installation with VP_VERSION and VP_SELF_SETUP_NO_MODIFY_PATH=1, and pass its absolute path with updater --vp. The final recipe completed successfully without depending on or changing machine-default VitePlus.
friction: Nested mise selected the pinned Zig command but build children found ambient Homebrew Zig. MISE_ACTIVATE_AGGRESSIVE=true makes nested child PATH prefer the selected toolchain; the actual fresh native build then passed.
decision: Assemble native release assets in a draft. Retry uploads only missing original assets, verify every existing asset against the candidate, then publish the complete verified draft. Conflicting or incomplete already-published releases remain failures and are never overwritten.
correction: Independent review found the REST release-by-tag endpoint excludes drafts; the original mock incorrectly served them. Promotion now locates pending drafts through the paginated releases list, fails on duplicate pending identities, and tests keep tag lookup404 until draft publication. Full promotion retry now covers a partial create/upload failure before the later notification failure.
correction: Root's machine-state audit established the earlier non-isolated `vp upgrade 1.3.0` trial changed the shared default from the session's initial1.4.0; root restored1.4.0. Only the final isolated VP_HOME recipe is demonstrated to preserve the default and skip shell-profile modification. Do not generalize that property to every exploratory trial in this task.
