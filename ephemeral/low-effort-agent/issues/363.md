# 363: Godoc comments that disagree with v0.36.0 behaviour

https://github.com/tylergannon/skgo/issues/363

These godoc comments disagree with the code at v0.36.0 (`3b382953`, which is also current `main`). They turned up while a new reference was being written from godoc. Each item gives the comment as it stands, what the code does, and suggested wording. All links point to `3b382953`.

## 1. Transport / Transported: the `src/hooks.ts` sample uses the wrong shape

Doc ([transport.go:54](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/transport.go#L54) and [transport.go:262-265](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/transport.go#L262-L265)):

```js
Money: { encode: (v) => v instanceof Money && [v.cents], decode: ([cents]) => new Money(cents) }
```

Code: the generated Go encoder sends an object `{cents}`, and the strict decoder refuses anything that is not an object with exactly that key ([example/internal/skgo/skgo_gen.go:367-394](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/example/internal/skgo/skgo_gen.go#L367-L394): `devalue.NewObject()` / `Set("cents", …)`, then `dvObject` and `dvKnown(obj2, at, "cents")`). The example's real hook uses the object shape ([example/web/src/hooks.ts:34-36](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/example/web/src/hooks.ts#L34-L36)). If you copy the godoc sample, `decode` destructures an object as an array, and every Money argument sent to Go is rejected.

Suggested:

```js
Money: {
	encode: (v) => v instanceof Money && { cents: v.cents },
	decode: (data) => new Money(data.cents)
}
```

It may also help to say that the encoded shape is the polytype projection of `T`'s JSON fields.

## 2. CookieOptions and SetCookie

[event.go:126-130](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/event.go#L126-L130):

> Path defaults to "/". Kit requires an absolute path in a remote function; SetCookie returns an error for anything else.
> Domain defaults to the request host.

- **Domain:** an empty Domain writes no `Domain` attribute ([event.go:412-414](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/event.go#L412-L414)), so the cookie is host-only. That differs from a cookie with `Domain=<host>`, which subdomains also receive. Kit behaves the same way. Suggested: "Domain is empty by default: the cookie has no Domain attribute and is host-only."
- **Path:** the relative-path refusal is in `cookieJar.set` ([event.go:306-309](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/event.go#L306-L309)). Every SetCookie goes through it, including from loads, page actions and `handle`, not only remote functions. Suggested: "Path defaults to "/". A non-empty Path must start with "/"; SetCookie returns an error otherwise."

[event.go:145-150](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/event.go#L145-L150), SetCookie:

> Only a `command` may do this. Kit throws "Cannot set cookies in `query` or `prerender` functions" everywhere else

Server loads, page actions and the `handle` hook all get mutable events ([loadevent.go:56](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/loadevent.go#L56), [document_action.go:78](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/document_action.go#L78), [middleware.go:275](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/middleware.go#L275)), so all of them may set cookies. The comment also leaves out two refusals in `mayWriteCookies` ([event.go:168-181](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/event.go#L168-L181)): a server route (`use http.SetCookie`), and a `handle` hook after its response has been generated. Suggested: "SetCookie writes a cookie on the response. Commands, forms, server loads, page actions and `handle` may call it. It returns an error in a query or prerender function (Kit's rule), in a server route (use http.SetCookie on the ResponseWriter), and in `handle` once the response has been generated."

## 4. HandleError: the scope is narrower than the comment says

Suggested scope sentence: "It runs for errors raised by server loads, page actions and page rendering on document and `__data.json` responses, for `handle` errors on document requests, and for panics in server routes. One more godoc claim that the code does not support (v0.36.0, 3b382953):

- `remote.go:408-420`, `BadRequest`: "The decoder's own diagnostic … is kept on the error for the server's logs". In practice nothing in SKGo logs it.
  - `badRequest.Unwrap` returns `*HTTPError`, so `handle_error.go:115-119` classifies it as an "app" error with `Err` nil, and the `handleError` hook never sees the detail.

  - The detail is reachable only by code that holds the original error and logs it itself.

  Suggest rewording to "kept on the error value (via `Error()`), but not sent and not logged by SKGo". The alternative is to actually log it, or to pass it to `handleError`.
