# 270: Cover remote relative fetch resolution against the logical caller page

https://github.com/tylergannon/skgo/issues/270

Request metadata now makes remote command/form relative fetches resolve against the caller's logical page URL, matching Kit. The behavior is correct, but the root suite does not protect the new metadata preference in Event.fetchURL.

Independent Opus stage-3 review demonstrated that deleting this preference from fetch.go leaves `go test -count=1 .` passing. This is a nonblocking regression-coverage gap in the RequestEvent branch.

Add a served remote-command fixture with caller headers for a concrete page, such as `/items/42`, and a relative `Fetch("data")`. Assert a literal receipt from `/items/data`, distinguishable from the remote transport URL. The test should fail when the logical-page preference is removed.
