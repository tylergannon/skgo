# 356: skgo update from web/src/routes stops at the generated boundary go.mod and updates only the CLI

https://github.com/tylergannon/skgo/issues/356

At v0.36.0 (`3b382953`, which is also current `main`), `skgo update` run from inside `web/src/routes/` (or any directory below it) does not find the application, and updates only the CLI.

**Doc:** the `--root` flag says "application root; otherwise locate the current application" ([cmd/skgo/update.go:15](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/cmd/skgo/update.go#L15)). The README says "Outside an application only the CLI and global vp are updated" ([README.md:345](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/README.md#L345)).

**Code:** `projectRoot` walks up from the working directory and stops at the first `go.mod` it finds ([internal/update/update.go:170-218](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/internal/update/update.go#L170-L218)). If that module does not require `github.com/tylergannon/skgo`, or has no sibling `web/package.json`, it returns `""` (`return "", nil`) and does not keep walking. An empty root means "outside an application".

`skgo generate` writes a module boundary at `web/src/routes/go.mod` whenever route links exist ([internal/gen/links.go:368-372](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/internal/gen/links.go#L368-L372); see [example/web/src/routes/go.mod](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/example/web/src/routes/go.mod)). That module requires nothing. So from `web/src/routes/`, or any route directory under it (where people edit `page.server.go` and `*.remote.go`), the first `go.mod` is the boundary. `projectRoot` returns `""`, and update quietly does the outside-an-application CLI-only update, even though the user is inside an application. Running from `web/` or `web/src/` works, because those directories have no `go.mod` and the walk reaches the root.

**Expected:** skip skgo's generated boundary module (it begins with the `// Code generated by skgo. DO NOT EDIT.` header) and keep walking to the nearest `go.mod` that requires skgo and has `web/package.json`. Alternatively, if the walk is inside a directory whose ancestor is an skgo application, fail with a message naming `--root`, rather than reporting a CLI-only update. Add a test that runs from `web/src/routes/<route>/` and checks the application root is selected.
