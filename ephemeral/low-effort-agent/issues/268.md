# 268: Protect typed resolve guard against repeated inner-hook execution

https://github.com/tylergannon/skgo/issues/268

The typed resolve guard rejects a second call, but the existing tests do not independently protect that guard: disabling its `called.CompareAndSwap` rejection leaves them green because the lower-level raw resolve guard still refuses the request.

Independent Opus review demonstrated this with a scratch mutation against RequestEvent checkpoint `1b0238e`. Production has the guard; this is a nonblocking regression-coverage gap.

Add a served case where the outer hook of a two-hook typed sequence calls resolve twice. Assert the inner hook executes exactly once, using an independently fixed expectation. Removing the typed guard should then fail the assertion even while the raw resolve guard remains intact.
