# 360: Generated .gitignore does not ignore .skgo/ build state

https://github.com/tylergannon/skgo/issues/360

At v0.36.0 (`3b382953`, which is also current `main`), the root `.gitignore` that `skgo new` writes does not ignore `.skgo/`, so local build-cache state shows up in `git status` after the first build.

**Template:** [internal/newapp/gofiles/dot-gitignore](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/internal/newapp/gofiles/dot-gitignore) contains only

```
/bin/
/web/node_modules/
```

**What writes `.skgo/` at the application root:** `skgo build` (and native builds, which use the same frontend preparation) records frontend freshness in `<root>/.skgo/build.json` and reads a one-shot `<root>/.skgo/import.json` receipt ([internal/webbuild/build.go:29](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/internal/webbuild/build.go#L29), [build.go:44](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/internal/webbuild/build.go#L44)). The fingerprint walk already treats `.skgo` as a non-source directory ([build.go:262](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/internal/webbuild/build.go#L262)).

**Not meant to be committed:** the README says "Delete `.skgo/` to invalidate frontend freshness" ([README.md:580-581](https://github.com/tylergannon/skgo/blob/3b382953fb97f77aecd1f5122d76dfbe586fec89/README.md#L580-L581)), which describes local cache state. A committed `build.json` would carry one machine's fingerprints to every clone. (Plugin state lives in `~/.skgo/`, not in the application.)

**Expected:** add `/.skgo/` to the template's `.gitignore`, and have a scaffold test check that `git status --porcelain` is clean after `just install` and a build. `skgo update` could also add the entry to existing applications, though it currently refuses to change authored configuration.
