## Finding 1 — issue: mapped crawl-query artifacts become HTTP-addressable through encoded question marks

The worklog requires preserved pathname-only request lookup, and `AGENTS.md` requires the bytes/status Go serves to follow Kit's native behavior. The map preserves the physical bytes correctly, but its logical inventory is also admitted unchanged to HTTP authority. `static.go:366` inserts every recorded path, including `/target?from=atlas` and `/only?query`, into `h.prerendered`. The new mapping is indexed into `h.prerenderedFiles` at `static.go:391`. `ServeHTTP` then uses Go's decoded `r.URL.Path` at `static.go:600`, and its direct set lookup at `static.go:695` resolves that decoded pathname through the mapped logical file at `static.go:751`.

For a request to `/only%3Fquery`, Go decodes `%3F` into the literal question mark in `URL.Path`; `RawQuery` is empty. This matches the crawl-inventory key `/only?query` and serves its relocated file. Native static middleware removes a literal search string before its URI decoding, preserves reserved `%3F`, and therefore does not select that query-bearing inventory entry. This policy is present in pinned [Kit 3.0.0 adapter-node `static.js`](https://raw.githubusercontent.com/sveltejs/kit/@sveltejs%2Fkit@3.0.0/packages/adapter-node/src/static.js), `split_url` and `serve_static`, and agrees with installed Kit's `decodeURI` use.
