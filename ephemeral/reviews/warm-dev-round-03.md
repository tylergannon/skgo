## Findings (most severe first)

### 1. issue — the Gimbal browser evidence records a failed navigation on every Go edit, unexplained

`/tmp/gimbal-browser-final.log` is the only Gimbal browser proof offered. It contains, between
the `go_body`, `api_field` and `repair` cases, the line
`FAILED http://127.0.0.1:48741/workflows { errorText: 'net::ERR_ABORTED' }` (three times; not
after `frontend_hmr` or `go_error`). Port 48741 is the supervisor's public address (Vite is
48742). Each case still reports `items: 8` afterwards, so the harness recovered, but the
harness source is not in the Gimbal worktree, the supervisor is no longer running, and nothing
in the log says whether the abort was a Playwright navigation superseded by Vite's
`full-reload`, a connection reset during `StopBeforeStart` handoff, or something else. The same
log shows the three Go cases taking 7.4 s, 11.8 s and 6.0 s, consistent with the "no
sub-second claim" context. Impact: the delivery context says no published Gimbal proof is
claimed before the pin, so this does not block the skgo release, but the final Gimbal
qualification must explain or eliminate the aborted navigation. An aborted navigation to the
supervisor during replacement is exactly the symptom a handoff bug would produce, and the
skgo `TestDevCanTransferAnExclusiveApplicationResource` fixture holds no in-flight browser
navigation across the handoff, so it would not catch it.

### 2. nitpick — legacy route-local projections lose skgo ownership after upgrade

`internal/gen/prune.go:85-89` recognises a Polytype-headed file as skgo's only under
`src/lib/skgo`. Before this branch, skgo wrote route-local `types.ts` beside Go source under
`web/src` (`types.go:327-329`) with the Polytype header. After upgrading, a stale one of those
whose Go declaration was removed before the first regeneration is never pruned (its first
regeneration would otherwise rewrite it with the skgo header). One-time, low impact, and the
safe direction per #313 ("do not infer ownership solely from Polytype's generic header").
Worth one line in the release note.

### 3. nitpick — `cmd/skgo` exercises only `--debug` at the CLI

`cmd/skgo/dev_test.go` passes `--debug` to its single live launch and asserts DWARF presence.
The fast default is proven in `internal/dev` (`TestDevBuildRetainsSymbolsAndOffersDWARF`,
which reads the child executable's sections and `go tool nm`) and by the round-02 plugin
experiment, so this is coverage shape rather than a gap.
