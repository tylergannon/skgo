## Findings

### 1. issue — two status surfaces still declare Kit 3.1.0

- `internal/sv/README.md:14`: "`skgo new` configures the project-local Kit
  3.1.0 prerender queue correction". This line was updated at the previous pin
  advance (#351 changed it from 3.0.0 to 3.1.0), so it is a maintained
  declaration of the generator, and npm ships a package README regardless of
  the `files` allowlist, so the published `@skgo/sv` would describe the wrong
  Kit.
- `docs/index.html:29`: "skgo uses SvelteKit 3.1.0, reviewed in the
  compatibility journal". This is the public status page. `docs/` requires
  permission to edit, but the journal's own step 6 ("Update this journal and
  the README status when the release is adopted") makes the mismatch a gap
  the change should have either fixed with permission or recorded as pending;
  neither the journal entry nor the worklog mentions it.

Impact: the mission is "coherently across supported pins, generator/updater
declarations"; after this branch merges, the generator's own README and the
public page contradict `toolchain.Kit`, the adapter peer and the README.
Reproduction: `grep -rn 'Kit 3.1.0\|SvelteKit 3.1.0' internal/sv/README.md docs/index.html`.

### 2. nitpick — `ephemeral/sveltekit-current/SKILL.md` contradicts itself on the queue qualification

Lines 71–72 still say the queue correction "is qualified against 3.1.0",
immediately followed by the new paragraph saying "the same correction is
qualified against 3.1.1". The header on line 10 says the verified version is
3.1.1. A reader following the skill's own instruction ("update the verified
version and this list only for facts verified") gets two answers.

### 3. nitpick — `kit-patch --apply` now silently downgrades a newer installed Kit

`internal/kitpatch/kitpatch.go:462-466`: `checkInstalledIfPresent` returns
nil for any installed `@sveltejs/kit` version that is not the supported one.
The comment and the worklog describe the earlier-Kit case, and the only test
covers 3.1.0 → 3.1.1. A project whose installed Kit is newer than
`toolchain.Kit` (previously a hard refusal) is now pinned down in
`package.json` and reported as "Installed @sveltejs/kit@<v> is replaced by
the native install". Since skgo supports exactly one Kit this may be intended,
but the output does not say "downgraded" and no test fixes the behaviour
either way. Not a user-hit problem today; recorded so the choice is explicit.

### 4. nitpick — `Verify`'s superseded refusal names an arbitrary entry

`internal/kitpatch/kitpatch.go:148-150` iterates a map and returns on the
first key. With more than one earlier owned entry the error names a
nondeterministic one. Harmless (the repair is the same `--apply`), but the
loop-with-immediate-return reads as a mistake.

### 5. nitpick — `internal/adapter/adapter.go` import grouping

The new `internal/toolchain` import sits in its own group between
`runtime/debug` and `sort`, splitting the standard-library block. gofmt is
clean, so this is style only; the rest of the file keeps stdlib together.
