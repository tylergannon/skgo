## Findings

### Nitpick: `EndpointConfig.Origin` still describes the old development mechanism

`endpoint.go:131-134` says that leaving `Origin` empty turns the CSRF check off, "which is what dev does." The fixed example deliberately retains the origin in development and now uses `EndpointConfig.Dev` to skip the check (`example/server.go:110-145`, `endpoint.go:580-582`). The API comment is therefore stale and may send a future caller back toward the exact split configuration this issue corrected. Reword it to say that an empty origin disables the check, while development mode skips it through `Dev`.

This does not affect runtime behavior or the adequacy of the proof.
