## Findings

No material findings remain. The nitpicks below would each make the first
implementation pass cleaner; none blocks starting Part A.

### 1. Nitpick — pin the remote ID and artifact path in the checked-in child test

**Category:** test anchoring (`CLAUDE.md`: never derive what you expect from
the thing you are testing).

`prerender_remote_ssr_test.go:129-150` discovers `nativeRemoteID` and
`nativeArtifactPath` by walking `ui/build` for a file named `noargValue`
containing the live literal, then splices them into the child test. That was
forced by a copied demo whose module layout the test did not own. A checked-in
fixture owns `src/routes/prerender-contract/fixture.remote.go`, so the remote
ID is a stable literal exactly as `prerender_inputs_minimal_build_test.go:143`
already pins `3215r6/empty`. §2 says "Keep exact artifact assertions" only for
§5; say the same for the production fixture's child test so the `p`-entry keys
(`<id>/W251bGxd`, `<id>/`) and the overlay path are literals, and the
"exactly one artifact" walk becomes an additional check rather than the
source of the expectation.

### 2. Nitpick — prove the bootstrap allowlist before authoring contracts

**Category:** ordering / feasibility.

The allowlist omits `web/pnpm-workspace.yaml`, `web/patches/`,
`web/pnpm-lock.yaml`, `web/static/` and `src/app.d.ts`. With `node_modules`
symlinked that is almost certainly fine (`prepareMinimalInputsApp` already
builds with `src` emptied, and the kept `vite.config.ts` carries everything
Kit needs: adapter, `paths.origin`, `experimental.remoteFunctions`,
`compilerOptions.experimental.async`, CSP auto mode). But no build has run on
this allowlist. Make the first Part A step a bootstrap-only build — the
allowlist plus one `+page.svelte` — so a missing file surfaces as its own
failure instead of inside the redirect or remote-artifact test. The same
applies before merging the adapter minimal apps in §5, since that test
currently keeps the whole `web/` directory rather than the allowlist.

### 3. Nitpick — "staged … when tests require mutation" understates staging

**Category:** wording.

§1's first sentence suggests some fixtures run in place. None can: a
`testdata` app has no `go.mod`, `go.sum` or `node_modules` until staging
composes them, and `GOWORK=off` runs need the rewritten `replace`. Say every
fixture is staged once per package invocation (into `packageTemp`), and that
mutation-bearing tests stage their own copy. This also keeps `go vet ./...`
honest: `testdata` is skipped, so the checked-in Go sources are only ever
type-checked inside a staged copy.

### 4. Nitpick — name the `ui`-root rewrites the allowlist implies

**Category:** completeness.

Copying `example/go.mod` brings `ignore ./web/node_modules` (`example/go.mod:7`)
and `tsconfig.json` brings `"include": ["src/**/*", …]` relative to the
frontend root. §1 says "rewrite … frontend-root paths as needed"; §4 would be
stronger if it listed the three concrete rewrites the `ui` root needs —
`ignore ./ui/node_modules`, `--web ../../ui` in `internal/skgo/config.go`,
and the `example/ui` embed import in `cmd/main.go` — since those are exactly
the edits the current tests perform by `replaceOnce` and the fixture should
instead author directly.
