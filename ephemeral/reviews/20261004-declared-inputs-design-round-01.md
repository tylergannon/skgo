## Finding 1 — issue: the listed cleanup hooks do not join native buildApp failure

**Missed requirement:** task worklog lines 11 and 15 require failure draining and real native crawler cancellation with zero live owned children, no private compile directory, and no late I/O. Referenced extension-plan lines 253–265 specify worker-triggered cancellation joined by `buildEnd(error)`, `adapt` finally, and an already-failing `closeBundle`.

**Source evidence:** installed Kit `src/exports/vite/build/index.js:439` performs postbuild work inside `buildApp`; native prerender is awaited at lines 792–814, while adaptation is deferred until line 909. Installed Vite `dist/vite/node/chunks/node.js:39822` closes each environment bundle before its build returns. Its application-level loop at lines 40212–40228 awaits plugin buildApp hooks without a failure/finally cleanup boundary. Kit `src/utils/fork.js:90–98` immediately rejects its worker promise on failure/nonzero exit; an async owner listener cannot delay that separate listener. Vite `dist/vite/node/cli.js:780–784` catches the resulting buildApp rejection and calls `process.exit(1)`.

**Causal failure:** a native crawler error exits its worker while another proxied Go body remains blocked. The main owner observes worker error/exit, marks the session closed, and begins cancellation. Kit's independent exit listener then rejects the prerender promise. SSR/client environment close hooks have already run, their buildEnd hooks do not encompass this later error, and adapt is never entered. Thus none of the named join points holds back the application's rejection while the children close. The CLI can enter the synchronous exit fallback and remove private files before the promised asynchronous drain finishes. Force-killing during synchronous exit is useful emergency containment but cannot establish the requested orderly close/reaping boundary. In a programmatic build, an error between successful prerender and adapt also bypasses these hooks and can retain a healthy owner's private directory/listeners until process exit.

**Bounded correction:** identify and implement a main-process terminal boundary covering the actual application build/postbuild promise, including failures before adapt. That boundary must await owner cancellation/close and directory cleanup before allowing the outer build to reject. Keep worker-local spawning prohibited, preserve the native failure, and retain the exit handler only as the fallback already described. Merely adding another environment buildEnd/closeBundle hook does not resolve this gap. The existing real native crawler-error fixture must prove cleanup before outer build completion; it must not accept only eventual cleanup after forced CLI exit. A targeted programmatic build failure before adapt can distinguish the boundary without introducing a new product subsystem.

## Other reviewed boundaries

No additional material finding remains in the additive typed Inputs API or the seven acceptance groups. Named local request-independent producers, strict matching of the body input, explicit undefined encoding for noarg producers, reserved-key rejection even for false/nil, and preservation of current declarations form a bounded contract. Native Kit runs every declared producer, enqueues noarg once even for an empty list, and owns canonical keys and URL-based response sharing; the proposed literal fixtures exercise those distinctions.

The parent explicitly clarified transport placement during this review: only serialized protocol JSON/devalue strings and envelope metadata cross parentPort. The requesting worker owns app transport encoders/decoders in its own module graph, encodes body payloads before sending, and decodes producer output before native enqueue. The main owner imports no app hooks and passes bytes through unchanged. This resolves the ambiguity created by moving the old combined launcher/codec initialization into shared infrastructure. Passing revived classes across parentPort would lose their prototypes, as documented in [Node 24 worker cloning](https://nodejs.org/download/release/v24.21.0/docs/api/worker_threads.html#considerations-when-cloning-objects-with-prototypes-classes-and-accessors); the clarified design avoids that failure and gives Money(125) its native worker-side identity.

The session/app-root/request-ID handshake, owner-fixed command, permanently shared compile promise, settle-once subprocess result rules, producer/infrastructure terminal failure, native treatment of structured body errors/redirects, process-tree termination, nonzero signal exit, and inert runtime helper are otherwise coherent design requirements. They still require implementation and the stated real native proofs. No result here establishes that any acceptance group already passes.
