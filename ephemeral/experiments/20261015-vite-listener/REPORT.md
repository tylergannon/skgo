## Structural blocker actually exposed

Adding a real `/listener-added` page made Kit's own generated client metadata contain `/listener-added:[2]` and shift `/orders` to `[~3]`; Go still returned nonempty GO_ERROR404 for the new route and emitted its fixed orders node2. Removing the page removed Kit's route metadata. The browser observed generated node2 import failure and HMR error/reload during the rapid add/remove. [Raw responses](structural.log), [captured generated client metadata](structural-client-metadata.js), [browser diagnostic](browser/structural-route-probe.json).

This isolates missing synchronized route/node/matcher/remote membership generation as a real remaining task. Ordinary component artifact replacement does not solve it. Pinned Kit `src/exports/vite/dev/index.js:101-145,225-238` owns add/unlink scanning and internal manifest replacement; its client update is not a Go manifest publication API. Remote export additions and structural Go rebuild fallback were not executed.

## Failures retained and what they changed

- `failure-bypass-target.log`: updating `bypass` options.target did not update the proxy's constructor defaults; the actual proxy still connected127.0.0.1:1. Configure now passes discovered target directly to standard proxy.web per request. Installed Vite bundled `dist/vite/node/chunks/node.js:25165-25196` contains that call path.
- `failure-nil-loads*.log`: SSR serving dereferenced nil loads; actual empty/new load registry fixed fixture composition.
- `failure-boundary-pending.log`: the Svelte boundary correctly rendered pending markup, so a separate real server-load became the native SSR assertion.
- `browser/initial-network.json`: broad application forwarding swallowed the configured `/.vite-listener/deps/*` tooling URLs, yielding Go404 and failed hydration despite good SSR. Added configured-cache exclusion; corrected browser baseline independently hydrated.
- `failure-stale-readiness*.log`: killing only the `go test` wrapper orphaned its test/Vite children. A later new Vite failed strictPort while HTTP200 came from the old root. Recovery readiness now checks own-root identity and child exit. This is a readiness/ownership defect found by the experiment, not successful collision handling.
- Validator positive→deliberate wrong-target FAIL→restored positive used literal expected label/origin/value in real Go HTTP tests with `-count=1`. A misrouted HTTP200 was correctly rejected. [Validator artifacts](../20261015-vite-listener-validation/).
