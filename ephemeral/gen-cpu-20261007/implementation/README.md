# Implemented generator resource reductions

The generator now uses compiler exports for dependency types while validating
the complete source-import closure as metadata. Fresh generated files load
through a temporary module view; project output remains buffered until normal
publication. The endpoint-module and empty-action-registry tests share one
immutable generated fixture and keep their independent assertions.

No concurrency or GC defaults changed. There is no persistent SKGo cache or
alternate test suite. This changes generation/checking, not request-time serving.

## Measured results

Go 1.27.1 darwin/arm64, parent GOMAXPROCS=10, existing child limit=2. Build
caches were warm; other agents also validated this machine. These observations
are not stable wall-time budgets. Allocations are cumulative, not live memory.

| Generator test process | Baseline | Implemented |
| --- | ---: | ---: |
| Sampled CPU | 758.68 CPU-seconds | 55.57 CPU-seconds |
| Profile allocation estimate | 118.74 GiB | 5.60 GiB |
| Standard-library source parses | 238,763 | 0 |
| Module-cache source parses | 21,532 | 0 |
| Package elapsed time | 200.52 s profile duration | 133.04 s test duration |
| Top-level tests executed | 105 | 107 |

The baseline includes the original 103 tests and two temporary probes. The
implemented run includes the same probes plus two new permanent contracts.
Public diagnostic coverage and the existing fresh-file assertion also expanded.
All 107 passed, with no skips. CPU fell 92.7% and sampled allocations 95.3%.
The implemented process's exact MemStats TotalAlloc was 6,020,307,200 bytes;
the table compares heap-profile estimates on both sides.

Baseline attribution establishes both causes: matcher loads parsed 40,482
standard-library files; fresh scanner loads parsed 86,945; fresh grammar loads
parsed 111,336. Restoring export reuse on only one loading path was insufficient.
All these parse counts cover the parent process; child CLI loads are separate.

The baseline generator-only process tree used 1,179.77 CPU-seconds and reported
8,097.89 MiB max RSS. The final **entire normal test invocation**, including both
modules and real example handler tests, used 745.47 CPU-seconds, took 160.34 s,
and reported 693.39 MiB max RSS. These have different scopes, so they are not a
matched suite percentage comparison. `time -l` max RSS is the largest reported
resident-set maximum, not the sum of concurrently resident processes.

## Matched process-tree check

One short before/after pair used the same two probe tests: two Run calls on an
example copy, followed by first generation of a fresh endpoint. The original
baseline executable and current executable ran sequentially after the full
normal run. Both passed. The current example generated bytes were unchanged.

| Same probe workload | Before | After |
| --- | ---: | ---: |
| Example allocations per Run | 1,504.9 / 1,508.6 MiB | 394.7 / 393.3 MiB |
| Fresh endpoint allocations | 300.8 MiB | 6.3 MiB |
| Fresh standard-library parses | 1,090 | 0 |
| Parent sampled CPU | 7.62 CPU-seconds | 2.82 CPU-seconds |
| Process-tree user + system CPU | 18.49 CPU-seconds | 13.18 CPU-seconds |
| Reported max RSS | 887.17 MiB | 217.16 MiB |
| Wall time | 9.42 s | 8.53 s |

The matched pair reduced process-tree CPU 28.7% and reported max RSS 75.5%,
so parent savings were not simply moved into child processes. Unchanged
example generation allocated about 74% less; fresh generation about 98% less.
The larger suite CPU reduction reflects avoiding many concurrent dependency
type-checks and their garbage collection, not a universal per-Run speedup.

## Confidence and execution

Independent validation found and verified repairs for decorator file identity,
embedded assets, and diagnostic path/column preservation, including later
relative line directives. Fault checks independently removed eight generated
behaviors, transitive import traversal, public Run/Check early refusal, and fresh
export reuse; the corresponding assertions failed. Reports and executable Go
overlay inputs are in
[independent validation](../../reviews/20261007-generator-resource-independent-validation.md)
and its
[final follow-up](../../reviews/20261007-generator-resource-validation-final-followup.md).

`just generate` left all tracked example generated output unchanged.
`just build` successfully built the production frontend. The final normal
`just test` invocation executed both modules and passed without skips. Temporary
compiler overlays added only observation/profiling and two diagnostic tests;
their sources are saved here and are absent from normal builds. The observer
preserves parser mode, source and filename; staged parser byte counts include
the synthetic source-location directive. Parent profiles exclude child CPU.

The final invocation selected the already-installed required native pnpm and
used test-specific verbosity, which Go ignores for child build/list commands:

```console
PATH="$HOME/.vite-plus/package_manager/pnpm/12.9.1/pnpm/bin:$PATH" \
GOFLAGS="-overlay=/Users/tyler/.codex/worktrees/3e0c/skgo/ephemeral/gen-cpu-20261007/implementation/final.overlay.json -test.v=true" \
/usr/bin/time -l just test
```

The observation overlay has absolute paths so subprocesses can use it from
fixture directories. Relocate those paths before reproducing in another tree.
The baseline compiler overlay is tied to checkpoint 2315164. The executables
were removed; profiles, exact logs, source overlays, and resource outputs remain.

Two unsuccessful normal invocations are retained separately. `first-attempt.*`
records the wrong ambient pnpm, missing example frontend build, and a diagnostic
column regression that was fixed. `verbose-attempt.*` records global `-v`
polluting child build output; test-specific `-test.v=true` repaired that
instrumentation error. Neither is green evidence. Full reruns were required
after those corrections; profiles were not rerun for additional summaries.

External package drivers keep their ordinary overlay protocol and may still
choose source loading. Overlays outside the host module keep ordinary loader
semantics. The temporary view is private to exact-package loads; wildcard
patterns would omit untouched symlinked directories. Missing compiler exports
can legitimately require source analysis. Cross-filesystem hardlink fallback
was not exercised on this machine. Browser qualification on main and a separate
person opening the example remain delivery requirements if merging/releasing;
this task made no Kit-facing interface change and does not claim release proof.
