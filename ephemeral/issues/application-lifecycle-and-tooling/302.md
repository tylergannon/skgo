# #302: new: frontend prepare emits a swallowed missing-remotes manifest error

https://github.com/tylergannon/skgo/issues/302
State: open

## Issue body

Fresh application creation emits a swallowed missing-manifest error during frontend installation, before Go generation writes the manifest. Observed with released `@skgo/sveltekit-adapter@0.22.1`, Kit3.0.0 and vp1.0.0, including the original #300 failure log and the independently reproduced bootstrap-fix run. This is separate from the companion-selection fix in #301.

```text
. prepare$ svelte-kit sync || echo ''
. prepare: > ENOENT: no such file or directory, open '.../web/skgo.remotes.json'
. prepare: at createPrerenderOwner (.../skgo-adapter/prerender.js:330:31)
...
skgo: wrote .../web/skgo.remotes.json
```

Creation subsequently generates and builds successfully, and the produced application serves HTTP200. The failure is nevertheless printed in a normal fresh-project workflow and swallowed by the upstream prepare script.

Expected: ordinary fresh-project preparation handles the not-yet-generated manifest without an opaque ENOENT stack trace, while actual build/runtime checks still require the generated manifest.

[Retained interactive creation transcript](https://github.com/tylergannon/skgo/pull/301#issuecomment-6094375342) and [independent review, including a separate reproduction](https://github.com/tylergannon/skgo/pull/301#issuecomment-6094426653). No fix for this pre-existing adapter behavior is included in #301.
