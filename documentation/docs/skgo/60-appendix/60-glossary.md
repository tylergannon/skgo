title: Glossary
summary: Terms this documentation uses that SvelteKit's does not.
---

SvelteKit's own [glossary](https://svelte.dev/docs/kit/glossary) covers rendering, routing and hydration terms, which mean the same thing here. These are the terms SKGo adds.

## Bindings package

The Go package at `internal/skgo` that `skgo generate` writes for an application. It registers every load, action, remote function and `server.go` route with the runtime and holds the generated `client`, `params` and `prerender` packages. Only `config.go` in it is yours; everything else is regenerated by `go generate ./...`. See [Generated files](project-structure#Generated-files).

## goja

The JavaScript engine, written in Go, that the production binary uses to run SvelteKit's server renderer. It has no Node built-ins and runs one render per runtime at a time; the binary keeps a pool of runtimes. See [Performance](performance#The-renderer-pool) and [UI libraries](integrations#UI-libraries).

## Link package

A copy of one route directory's Go files under `internal/skgo/links/<base32>`, where the directory name encodes the route path. Go cannot import a path containing `[slug]` or `(group)`, so the Go compiler sees the copies, and `internal/skgo/links.json` maps each copy back to its route directory. `go generate ./...` refreshes them.

## Locals

The Go struct in `internal/app/locals.go` that plays the part of Kit's `App.Locals`. The `handle` hook fills it once per request and every load, action, remote function and `server.go` handler reads it, through `event.Locals` or `app.LocalsFrom(ctx)`. See [Auth](auth).

## Marker

The `var _ = skgo.Query(fn)` line that declares a remote function. `skgo.Query`, `skgo.Command`, `skgo.Form`, `skgo.BatchQuery`, `skgo.LiveQuery` and `skgo.Prerender` return a `skgo.Marker`, which carries nothing at run time; the generator reads the declaration. See [Remote functions](remote-functions).

## Origin

The scheme and host the application is served from, fixed at build time: `just build` passes it to Vite as `ORIGIN` for Kit's `paths.origin` and compiles the same value into the binary, and `-origin` overrides it. The Go server uses it to refuse cross-site form-shaped posts and non-GET remote calls, and to decide whether a cookie is `Secure`. See [Deploying](deploying).

## Prerender service

The program under `internal/skgo/prerender` that the adapter runs during `vp build`. It serves the application's loads and remote functions to Kit's prerenderer over `skgo.RunPrerenderService`, so prerendered pages are rendered with real Go data. See [Prerendering](prerendering).

## Remote ID

The string Kit's client uses to call a remote function, `<hash>/<name>`, where the hash identifies the `.remote.go` file. `Remote.ID()` returns it, and the request path is `/_app/remote/<id>`. See [Testing](testing#Testing-the-Go-server).

## Renderer pool

The set of goja runtimes the production handler keeps warm, each holding a compiled copy of the server bundle. `SSROptions.Runtimes` sizes it and defaults to one per CPU. See [Performance](performance#The-renderer-pool).

## Stub

A generated TypeScript module, such as `+page.server.ts` or `todos.remote.ts`, whose exports have the right types and whose bodies throw `skgo: implemented in Go`. Kit compiles the stubs for type checking and for the client; the Go server answers the requests. See [Project structure](project-structure#Generated-files).
